3. 埋め込みの生成と推論

埋め込みモデルにとっての「生成」とは、入力からベクトルを 1 本作ることです。 そのときに利用者が選べるつまみ —— タスク接頭辞・出力次元・視覚トークン予算・量子化 —— が、 品質とコストをどう動かすのかを、論文の付録 A・§3.4・Table 1 から読みます。

上 4 つは非対称タスク(短いクエリで長い文書を引く)で、クエリとターゲットに別の書式を使います。 下 3 つは対称タスクで、すべての入力に同じ接頭辞を付けます。 評価もこの 7 種類の指示で行われます(§4.1)。 接頭辞はテキストですが、続く {text} の位置には画像・音声・動画のソフトトークンも入れられます (アーキテクチャ編の系列化)。

⚠️ 擬似コード — 論文の式 (1)・付録 A・§2.2 から再構成(配布ライブラリの実際の API ではありません)
# 公開モデルの呼び出し方(ライブラリ名・関数名)は論文に書かれていないため、
# ここでは `model.embed(segments)`(区間のリスト x = (s_1, …, s_M) を受け取り、§2.2 の通り
# テキストはトークン化、画像・音声はエンコーダに通して 1 本の系列にする)という架空の関数で手続きだけを示します。
import numpy as np

QUERY  = "task: search result | query: {}"
TARGET = "title: {} | text: {}"

# ① オフライン: ターゲットを埋め込んで索引化(画像・音声は text の位置に差し込まれる)
# 入力は「区間 (segment) のリスト」: 文字列はテキスト区間、画像・音声はメディアのまま渡す。
# (str.format に画像を埋め込むと文字列化されてしまうので、接頭辞とメディアは別区間にする)
docs = [["title: none | text: ", image_of_strings],          # 🖼️ テキスト区間 + 画像区間
        ["title: none | text: ", audio_of_chord],            # 🔊 テキスト区間 + 音声区間
        [TARGET.format("ギター入門", "コードの押さえ方…")]]   # 📝 テキスト区間のみ
P = np.stack([model.embed(segs) for segs in docs])         # [N, 768], 各行 ‖·‖=1

# ② 次元を節約したいなら先頭を切って再正規化 (MRL: 768/512/256/128)
k = 256
P_k = P[:, :k] / np.linalg.norm(P[:, :k], axis=1, keepdims=True)

# ③ オンライン: クエリを埋め込み、内積で上位を返す
q = model.embed([QUERY.format("開放弦の音は?")])[:k]
q /= np.linalg.norm(q)
top = np.argsort(-(P_k @ q))[:10]

視覚トークン予算 — 推論時に「解像度」を選ぶ(§3.4, Table 5)

学習時は画像 280・動画フレーム 140 トークンですが、Gemma 4 の視覚エンコーダは 70〜1120 の予算に対応しています。 では推論時に予算を変えると何が起きるか。中間チェックポイント(学習 280 / 140)で評価予算を振った結果が次の図です。

論文の解釈(§3.4)は 3 つに分かれます。

  • 文書画像は細部に敏感で、学習時の予算(280)を超えても伸び続ける(560 で 67.62)
  • 一般画像は集計では 280 で頭打ち(個別タスクではまだ伸びるものもある)
  • 動画は 280 → 560 でむしろ劣化。理由として “the excessive sequence lengths dilute attention and mean-pooled representations” を挙げます。 平均プーリングは全トークンを等しく平均するので、フレームあたりのトークンが増えるほど 1 トークンの寄与は薄まります

Table 5(下段)。動画を 70 トークンで学習すると、70 で評価したときの動画だけは良くなる(46.60 vs 45.79)。 しかし画像・文書画像は下がり、140 で評価すると全モダリティで負けます。 論文の説明は、(a) 単一画像タスクは 280 で学習されており 70 トークンの動画フレームから恩恵を受けない別モダリティ扱いになる、 (b) 粗い動画表現は一般的な視覚表現に転移するはずの空間的ディテールを捨ててしまう、の 2 点。 結論として学習は 140 のままが両方の評価条件で好ましいとし、 学習予算をさらに上げる余地はあるものの「収穫逓減かつ大きな計算コスト」と見ています。

この節の数値は中間レシピのもの Table 5 の上段と下段は別の中間レシピで回された実験で、最終モデルの数値でもありません。 また最終評価(§4)は画像 280・動画フレーム 140・最大 32 フレームという「現実的な使い方」で測られており、 論文は「より大きな予算なら特に文書画像でさらに伸びうる」と注記しています(§4.1)。
