# EmbeddingGemma 2 図解 — トピック概要と作成プロセスの記録

## このトピックについて

*EmbeddingGemma 2: Unified and Efficient Multimodal Representations*
(EmbeddingGemma Team, Google DeepMind / [arXiv:2610.37364](https://arxiv.org/abs/2610.37364), 2026-10-27)は、
テキスト・コード・画像・音声・動画、およびそれらの混在入力を **1 つの 768 次元空間**に写す
**744M パラメータのオープンなマルチモーダル埋め込みモデル**の技術報告。
本シリーズで先に扱った NExT-GPT / CoDi-2 / BAGEL / NWM が「生成するモデル」だったのに対し、
本作の出力は **単位ノルムのベクトル 1 本** である。

## 「コードなし」トピックとしての方針(BeyondLM 回と同じ)

1. **論文の数式をそのまま**(式 (1)〜(6)、PLE の 4 式)
2. **論文の表の数値を再掲**(Table 1〜11、付録 A・B)
3. **擬似コード**(損失の実装イメージ、検索での使い方)。必ず `⚠️ 擬似コード` と明記し、
   論文に記載のない値(温度 τ、損失間の重み、ライブラリ API)は補わず引数・架空関数のままにした

論文の Figure 2(パレートフロンティア)は散布図で数表がないため、
**本文の Table 7〜10 に数値があるモデルだけ**で描き直し、その旨を図の注記に書いた。
検索フロー図の文書例と類似度の数値は説明用の架空のもので、図中に明記した。

## このトピックの読みどころ(調査で拾った論点)

1. **PLE の専用表を捨てると、テキストでも良くなる** — 専用表は非テキストのソフトトークンに信号を与えられない。射影だけにして MMEB-v2 +0.39(Table 2)
2. **双方向化の適応段を挟まない** — テキスト事前 FT(ほぼ蒸留)が暗黙のウォームアップを兼ねる
3. **2 つの切り替え点がずれたカリキュラム** — モダリティは ①→②、目的関数は ②→③ で切り替わる
4. **蒸留は頭打ちし、対照 FT が教師を超えさせる** — 計算量を揃えた比較で +3.19(Table 3)
5. **視覚エンコーダは凍結せず学習** — +4.09(Table 4)。ただし音声エンコーダは凍結のまま
6. **前作から外したもの** — ハードネス重み付け(ノイズ正例の増幅・モダリティ間の勾配スケール不均衡のため)
7. **同タワー負例** — クエリ群とターゲット群が別の部分空間に固まるのを防ぐ
8. **視覚トークン予算はモダリティで最適値が違う** — 文書画像は 560 でも伸び、動画は 560 で劣化
9. **パラ言語情報は「奥にしまわれている」** — 性別クラスタリング 0.40 だが線形プローブでは 66.40
10. **ネイティブ音声は ASR 経由より +12** — 256 次元でもフル次元 ASR を上回る
11. **英語テキストは前作より後退** — 多モダリティ化と小型化のコストが見える箇所
