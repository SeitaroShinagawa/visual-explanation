2. 学習プロセス

NWM の学習は拡散モデルの標準的な学習そのもので、 凝った損失も、段階的なカリキュラムもありません。 工夫はすべて「1 サンプルをどう作るか」に集中しています —— 行動をどう正規化するか、ゴールを何個引くか、時間シフトをどう混ぜるか。

何を食わせるか — 5 つのロボットデータセットと Ego4D

NWM はタスク埋め込みも身体(embodiment)埋め込みも持ちません。 四輪車も、四足歩行ロボットも、オフロード ATV も、屋内 Roomba も、 全部まとめて 1 本のデータセットとして流し込みます。

行動はどう作られるか — 生のオドメトリから 3 つのスカラーへ

ロボットデータセットに入っているのは position と yaw の時系列です。 これが「行動」になるまでに、3 段階の変換を経ます。

datasets.py L129–159 BaseDataset._compute_actions GitHub ↗
    def _compute_actions(self, traj_data, curr_time, goal_time):
        start_index = curr_time
        end_index = curr_time + self.len_traj_pred + 1
        yaw = traj_data["yaw"][start_index:end_index]
        positions = traj_data["position"][start_index:end_index]
        goal_pos = traj_data["position"][goal_time]
        goal_yaw = traj_data["yaw"][goal_time]
        ...
        waypoints_pos = to_local_coords(positions, positions[0], yaw[0])
        waypoints_yaw = angle_difference(yaw[0], yaw)
        actions = np.concatenate([waypoints_pos, waypoints_yaw.reshape(-1, 1)], axis=-1)
        actions = actions[1:]

        goal_pos = to_local_coords(goal_pos, positions[0], yaw[0])
        goal_yaw = angle_difference(yaw[0], goal_yaw)

        if self.normalize:
            actions[:, :2] /= self.data_config["metric_waypoint_spacing"]
            goal_pos[:, :2] /= self.data_config["metric_waypoint_spacing"]

        goal_pos = np.concatenate([goal_pos, goal_yaw.reshape(-1, 1)], axis=-1)
        return actions, goal_pos
なぜヨーだけ正規化しないのか normalize_data が触るのは [:, :2]、つまり xy だけです。ヨーはラジアンのまま渡されます。 これはヨーがもともと有界(\([-\pi, \pi]\))で、スケールが環境に依存しないからです。 angle_difference が \(2\pi\) の周期性を畳んで必ずこの範囲に収めるので、 xy のように「データセットごとに違うメートル値」を揃える処理が要りません。

実際、デモノートブックの回転コマンドは 'Rotate Left': [0, 0, 0.5] —— 0.5 ラジアン(約 29°)という素直な物理量になっています。

1 観測につきゴール 4 つ — 「行動と時間のもつれ」への対策

概要編で触れた「モデルが時間だけ見て行動を無視する」危険への対策が、 データローダの __getitem__ に埋め込まれています。

datasets.py L183–206 TrainingDataset.__getitem__ GitHub ↗
    def __getitem__(self, i: int) -> Tuple[torch.Tensor]:
        f_curr, curr_time, min_goal_dist, max_goal_dist = self.index_to_data[i]
        goal_offset = np.random.randint(min_goal_dist, max_goal_dist + 1, size=(self.goals_per_obs))
        goal_time = (curr_time + goal_offset).astype('int')
        rel_time = (goal_offset).astype('float')/(128.) # TODO: refactor, currently a fixed const

        context_times = list(range(curr_time - self.context_size + 1, curr_time + 1))
        context = [(f_curr, t) for t in context_times] + [(f_curr, t) for t in goal_time]

        obs_image = torch.stack([self.transform(Image.open(get_data_path(self.data_folder, f, t))) for f, t in context])

        # Load other trajectory data
        curr_traj_data = self._get_trajectory(f_curr)

        # Compute actions
        _, goal_pos = self._compute_actions(curr_traj_data, curr_time, goal_time)
        goal_pos[:, :2] = normalize_data(goal_pos[:, :2], self.ACTION_STATS)

        return (
            torch.as_tensor(obs_image, dtype=torch.float32),
            torch.as_tensor(goal_pos, dtype=torch.float32),
            torch.as_tensor(rel_time, dtype=torch.float32),
        )

返るテンソルの形は順に obs_image: (8, 3, 224, 224)、goal_pos: (4, 3)、 rel_time: (4,) です。ここで押さえるべきは 3 点です。

  • 返る画像は 8 枚 —— 文脈 4 枚(context_times)に続けてゴール 4 枚。 1 本のテンソルに連結されて返る
  • goal_offset は負にもなる —— min_dist_cat = -64 なので、「64 フレーム前に戻る」というサンプルも作られます。 時間シフトは未来だけでなく過去も含む
  • 行動は「1 手ずつ」ではなく「ゴールまでの相対姿勢」 —— モデルに渡されるのは actions ではなく goal_pos です。 これがまさに論文 Eq. (2) の総和 \(u_{\tau \to m}\) に相当します
マジックナンバー 128 の正体 rel_time = goal_offset / 128. にはコード自身が # TODO: refactor を付けています。 128 = 2 × 64 で、min_dist_cat = -64 / max_dist_cat = +64 と対応しており、 rel_t がちょうど \([-0.5, +0.5]\) に収まるようになっています。 4 FPS のデータなので ±64 フレーム = ±16 秒 —— 論文の “we allow time shifts of up to ±16 seconds” と一致します。

推論側(isolated_nwm_infer.py L75)でも rel_t = (torch.ones(B) * (1./128.)) * num_timesteps と、同じ 128 がハードコードされています。 この定数を変えるなら 2 か所を同時に直す必要があります。

拡散の学習 — 論文の式とコードの実装

論文 §3.2 は損失をこう書きます。

論文の学習目的関数 順過程(ノイズを載せる): $$s^{(t)}_{\tau+1} = \sqrt{\alpha_t}\, s_{\tau+1} + \sqrt{1 - \alpha_t}\, \epsilon, \qquad \epsilon \sim \mathcal{N}(0, I)$$ 逆過程の学習目的: $$\mathcal{L}_{\text{simple}} = \mathbb{E}\left[\left\| s_{\tau+1} - F_\theta\!\left(s^{(t)}_{\tau+1} \mid \mathbf{s}_\tau, a_\tau, t\right) \right\|_2^2\right]$$ 加えて “we also predict the covariance matrix of the noise and supervise it with the variational lower bound loss \(\mathcal{L}_{\text{vlb}}\)” とあります。 ノイズスケジュールとハイパーパラメータは DiT に従う、とも明記されています。

実装の癖 — 2 つの小さな引っかかり ① opt.zero_grad() の位置は 2025-07-29 に修正されたばかりです。 それ以前は if not bfloat_enable: の内側にあり、 bfloat16 で学習すると勾配が毎ステップ累積していく不具合がありました (コミット 7782ade “fix zero_grad bug”)。 古い fork を使う場合は要確認です。

② bfloat16 なのに GradScaler を使っています(L142)。 勾配スケーリングは本来 float16 のアンダーフロー対策で、 指数部が float32 と同じ bfloat16 では不要です。害はありませんが、 scaler.unscale_() を挟んでから勾配クリップする流れは float16 前提の書き方が残ったものと読めます。

学習コードに「無いもの」

このコードベースを読むうえで、拡散モデルの定番なのに存在しないものを確認しておくと理解が早まります。

定番の要素NWM では理由(推測を含む)
Classifier-Free Guidance のための条件ドロップアウト 無い。train.py L258 のコメント “This enables embedding dropout for classifier-free guidance” は DiT からの残骸で、 CDiT にラベルドロップ機構は実装されていない 行動条件は「創造性」ではなく忠実さが要る。 CFG で条件を強調する必要も、無条件生成を学ぶ必要もない
学習率スケジューラ 無い。定数 8e-5 データを足しても学習を再開しやすい(BAGEL の CT/SFT と同じ発想)
重み減衰 weight_decay=0 DiT の設定を踏襲
複数ステージのカリキュラム 無い。最初から最後まで同じ設定 単一の目的関数しかないので、段階を分ける動機が無い
方策・報酬・価値関数 無い そもそも学習していない。行動選択は推論時の最適化に置かれている

この章のまとめ

NWM の学習を 4 点で
  1. 損失は拡散の標準そのもの(\(\epsilon\) の MSE + 変分下界)。重み調整も段階分けも無い
  2. 工夫はサンプルの作り方に集中している —— 行動を局所座標に回して歩幅で割り、\([-1,1]\) に正規化する 4 段階
  3. 1 観測につきゴール 4 つ。同じ文脈から違う行動・違う時刻へ分岐するペアを 必ずバッチに並べ、「時間だけ見る」ショートカットを塞ぐ
  4. 時間シフトは過去にも遡れる(−64 〜 +64 フレーム)。 「世界の時間軸を前後に動かす」ことまで学習対象に入っている

次章では、学習し終えたモデルをどう動かすか —— 2 つの生成モードと、 その上に載る計画(planning)の実装を見ます。
