1. アーキテクチャ詳解

Conditional Diffusion Transformer(CDiT)は、DiT から 「文脈を self-attention に入れない」という一手だけを引き算し、 代わりに cross-attention を足したモデルです。 その一手がなぜ効くのかを、テンソル形状と計算量から確かめます。

まず全体のテンソル形状を押さえる

CDiT が扱うのは画像そのものではなく、Stable Diffusion の VAE が吐く潜在テンソルです。 224×224 の RGB 画像が 28×28×4 に圧縮され、そこからさらに 2×2 のパッチに切られてトークンになります。

CDiT ブロック — 3 段構成と、その順番の意味

まずコードそのものを見てしまうのが早道です。ブロックの本体はたった 7 行です。

models.py L83–110 GitHub ↗
class CDiTBlock(nn.Module):
    """
    A DiT block with adaptive layer norm zero (adaLN-Zero) conditioning.
    """
    def __init__(self, hidden_size, num_heads, mlp_ratio=4.0, **block_kwargs):
        super().__init__()
        self.norm1 = nn.LayerNorm(hidden_size, elementwise_affine=False, eps=1e-6)
        self.attn = Attention(hidden_size, num_heads=num_heads, qkv_bias=True, **block_kwargs)
        self.norm2 = nn.LayerNorm(hidden_size, elementwise_affine=False, eps=1e-6)
        self.norm_cond = nn.LayerNorm(hidden_size, elementwise_affine=False, eps=1e-6)
        self.cttn = nn.MultiheadAttention(hidden_size, num_heads=num_heads, add_bias_kv=True, bias=True, batch_first=True, **block_kwargs)
        self.adaLN_modulation = nn.Sequential(
            nn.SiLU(),
            nn.Linear(hidden_size, 11 * hidden_size, bias=True)
        )

        self.norm3 = nn.LayerNorm(hidden_size, elementwise_affine=False, eps=1e-6)
        mlp_hidden_dim = int(hidden_size * mlp_ratio)
        approx_gelu = lambda: nn.GELU(approximate="tanh")
        self.mlp = Mlp(in_features=hidden_size, hidden_features=mlp_hidden_dim, act_layer=approx_gelu, drop=0)

    def forward(self, x, c, x_cond):
        shift_msa, scale_msa, gate_msa, shift_ca_xcond, scale_ca_xcond, shift_ca_x, scale_ca_x, gate_ca_x, shift_mlp, scale_mlp, gate_mlp = self.adaLN_modulation(c).chunk(11, dim=1)
        x = x + gate_msa.unsqueeze(1) * self.attn(modulate(self.norm1(x), shift_msa, scale_msa))
        x_cond_norm = modulate(self.norm_cond(x_cond), shift_ca_xcond, scale_ca_xcond)
        x = x + gate_ca_x.unsqueeze(1) * self.cttn(query=modulate(self.norm2(x), shift_ca_x, scale_ca_x), key=x_cond_norm, value=x_cond_norm, need_weights=False)[0]
        x = x + gate_mlp.unsqueeze(1) * self.mlp(modulate(self.norm3(x), shift_mlp, scale_mlp))
        return x

forward は 4 行しかありません —— ①自己注意 → ②交差注意 → ③MLP、そのすべてが 1 行目で作った 11 本の変調係数で味付けされる、という構造です。 cross-attention の直前で x_cond 側も変調されている(L107)ことに注意してください。

なぜ AdaLN が 11 分割なのか

DiT の AdaLN は 6 * hidden_size(self-attention の shift/scale/gate と MLP の shift/scale/gate)でした。 CDiT はこれが 11 になっています。増えた 5 本の内訳は次の通りです。

係数何を変調するかDiT にもある?
shift_msa, scale_msa, gate_msaself-attention(3 本)あり
shift_ca_xcond, scale_ca_xcondcross-attention の key/value 側(= 文脈の LayerNorm 出力)なし
shift_ca_x, scale_ca_x, gate_ca_xcross-attention の query 側なし
shift_mlp, scale_mlp, gate_mlpMLP(3 本)あり
見落としやすい設計 — 文脈も条件で変調される shift_ca_xcond / scale_ca_xcond があるおかげで、同じ文脈フレームでも 「どんな行動を取るか」によって違う見え方をします。 文脈を静的な参照テーブルとして扱うのではなく、 行動と時間シフトに応じて読み方を変えられるようにしてあるわけです。

なお gate は cross-attention の出力側にだけ付き(gate_ca_x)、 文脈側には付きません —— gate は残差に足し込む量を制御する係数なので、 残差の主体である query 側にしか意味がないためです。

ブロックの 4 割は AdaLN です。 DiT の 6 分割でも 7.97 M(DiT-XL ブロックの 33%)を占めていたので、 これは DiT 系の設計に共通する性質でもあります。 「たった 4 つのスカラーを条件にするだけなのに、なぜ 1B のモデルが要るのか」という疑問の 答えの一部がここにあります —— 条件の情報量が小さいことと、 それを全層に反映させる機構が軽いことは別問題です。

条件ベクトル ξ の作り方

論文 Eq. (3) の \(\xi = \psi_a + \psi_k + \psi_t\) は、コードでは forward のたった 4 行です。

models.py L226–245 CDiT.forward GitHub ↗
    def forward(self, x, t, y, x_cond, rel_t):
        x = self.x_embedder(x) + self.pos_embed[self.context_size:]
        x_cond = self.x_embedder(x_cond.flatten(0, 1)).unflatten(0, (x_cond.shape[0], x_cond.shape[1])) + self.pos_embed[:self.context_size]
        x_cond = x_cond.flatten(1, 2)
        t = self.t_embedder(t[..., None])
        y = self.y_embedder(y)
        time_emb = self.time_embedder(rel_t[..., None])
        c = t + time_emb + y # if training on unlabeled data, dont add y.

        for block in self.blocks:
            x = block(x, c, x_cond)
        x = self.final_layer(x, c)
        x = self.unpatchify(x)
        return x

c = t + time_emb + y —— この 1 行が Eq. (3) です。 3 つの埋め込みを連結ではなく加算している点に注目してください。 連結なら次元が 3 倍になりますが、加算なら \(d\) のままです。 AdaLN が全ブロックにこの \(d\) 次元ベクトルを配るので、次元を増やすとコストが 3 倍になってしまいます。

末尾のコメントが示す「ラベルなしデータ」の扱い # if training on unlabeled data, dont add y. —— 論文 §3.2 の “To train on unlabeled data, we simply omit explicit navigation actions when computing ξ” に対応するコメントですが、公開コードにこの分岐は実装されていません。 c = t + time_emb + y は常に 3 項を足します。 Ego4D を使った実験(評価編)を再現するには、 このコメントに従って自分で分岐を書く必要があります。 関連して、config/data_config.yaml にも Ego4D のエントリはありません。

行動埋め込み — 3 つのスカラーを別々の MLP に通す

models.py L65–77 GitHub ↗
class ActionEmbedder(nn.Module):
    """
    Embeds action xy into vector representations.
    """
    def __init__(self, hidden_size, frequency_embedding_size=256):
        super().__init__()
        hsize = hidden_size//3
        self.x_emb = TimestepEmbedder(hsize, frequency_embedding_size)
        self.y_emb = TimestepEmbedder(hsize, frequency_embedding_size)
        self.angle_emb = TimestepEmbedder(hidden_size -2*hsize, frequency_embedding_size)

    def forward(self, xya):
        return torch.cat([self.x_emb(xya[...,0:1]), self.y_emb(xya[...,1:2]), self.angle_emb(xya[...,2:3])], dim=-1)

論文の “we first map each scalar to \(\mathbb{R}^{\frac{d}{3}}\) by extracting sine-cosine features, then applying a 2-layer MLP, and concatenating them into a single vector \(\psi_a \in \mathbb{R}^d\)” がそのままコードになっています。

  • 3 成分それぞれに独立した埋め込み器を持つ —— Δx、Δy、Δyaw は物理的に別の量なので、重みを共有しない
  • 拡散 timestep と同じ TimestepEmbedder を使い回している —— sin-cos 周波数特徴(256 次元)→ Linear → SiLU → Linear。 連続値をそのまま線形層に入れるより、周波数展開してからのほうが細かい差を拾える
  • \(d\) が 3 で割り切れない場合(1152 は割り切れるが 1024 は割り切れない)は、 角度の埋め込みが余りを吸収する(hidden_size - 2*hsize)

位置埋め込み — フレームの順番はここで表現される

models.py L159 GitHub ↗
        self.pos_embed = nn.Parameter(torch.zeros(self.context_size + 1, num_patches, hidden_size), requires_grad=True) # for context and for predicted frame

形状が (context_size + 1, num_patches, hidden_size) = (5, 196, d) であることに注目してください。 フレームの位置ごとに、196 パッチ分の位置埋め込みを丸ごと別々に持っています。 時間方向の位置埋め込みと空間方向の位置埋め込みを分けて足す設計ではなく、 (時刻, 空間位置) の組ごとに独立したベクトルを学習するわけです。

  • pos_embed[:4] が文脈フレーム用、pos_embed[4:] が生成対象用。 生成対象は文脈とは違う位置埋め込みをもらうので、 cross-attention の中で「自分は未来のフレームだ」と区別できる
  • ファイル末尾に get_2d_sincos_pos_embed(MAE 由来)が定義されていますが、 CDiT では使われていません。実際には nn.init.normal_(std=0.02) で 初期化された学習可能パラメータです (コメントの “Initialize (and freeze) pos_embed by sin-cos embedding” は DiT からの残骸)
  • この設計の帰結として、文脈長を学習後に変えられません。 context_size を変えると pos_embed の形状が変わり、 チェックポイントを strict=True で読み込めなくなります

DiT ではなく CDiT にする理由 — 計算量

論文 §3.2 の議論は明快です。トークン次元 \(d\)、1 フレームあたりのトークン数 \(n\)、文脈フレーム数 \(m\) として:

論文 §3.2 の計算量 DiT(文脈も全部 self-attention に入れる): $$O(m^2 n^2 d) \quad \text{—— 文脈長に対して} \textbf{二乗}$$ CDiT(支配項は cross-attention): $$O(m n^2 d) \quad \text{—— 文脈長に対して} \textbf{線形}$$ “allowing us to use longer context size”。
論文が「驚いた」と書いている結果 “Surprisingly, even with equal amount of parameters (e.g, CDiT-L compared to DiT-XL), CDiT is 4× faster and performs better.”

CDiT-L と DiT-XL が同規模というのは実際に数えられます —— CDiT-L/2 は約 687M、DiT-XL/2 は約 675M(本解説で models.py の定義から 手計算した値。ブロック内訳は下表)。 つまり「小さいから速い」のではなく、同じ大きさのまま速くて強いという主張です。

初期化 — ゼロから立ち上がる仕掛け

initialize_weights(L165–209)には、DiT 系に共通する 2 つのゼロ初期化があります。

models.py L200–209 GitHub ↗
        # Zero-out adaLN modulation layers in DiT blocks:
        for block in self.blocks:
            nn.init.constant_(block.adaLN_modulation[-1].weight, 0)
            nn.init.constant_(block.adaLN_modulation[-1].bias, 0)

        # Zero-out output layers:
        nn.init.constant_(self.final_layer.adaLN_modulation[-1].weight, 0)
        nn.init.constant_(self.final_layer.adaLN_modulation[-1].bias, 0)
        nn.init.constant_(self.final_layer.linear.weight, 0)
        nn.init.constant_(self.final_layer.linear.bias, 0)
  • AdaLN の最終 Linear がゼロ → 学習開始時は shift=0, scale=0, gate=0。modulate(x, 0, 0) = x かつ gate * attn(...) = 0 なので、全ブロックが恒等写像として始まる (これが “adaLN-Zero” の由来)
  • FinalLayer の Linear もゼロ → 最初の予測は常にゼロテンソル。 「何も予測しない」状態から徐々に立ち上がる

つまり初期状態の CDiT は「何をしても出力ゼロ」で、 学習が進むにつれてブロックが 1 つずつ「効き始める」構造になっています。 深いモデルを安定に学習させるための、DiT 由来の作法です。

この章のまとめ

CDiT の設計を 4 点で
  1. self-attention は生成対象だけ。文脈は cross-attention 経由でしか入らない → 計算量が文脈長に対して線形になる
  2. 文脈トークンはブロックを通しても更新されない → 各層が同じ x_cond を参照するだけで済む
  3. 条件は 4 つのスカラー(Δx, Δy, Δyaw, k)+ 拡散 timestep のみ。 sin-cos 展開 → MLP → 加算 → AdaLN で全層に配る
  4. 位置埋め込みは (時刻, 空間) の組ごとに学習。 そのぶん文脈長は学習後に変えられない

次章では、このモデルに何を食わせて学習するのかを見ます —— とくに「行動」がどうやって生の GPS/オドメトリから 3 つの正規化スカラーになるのか、 そして「1 観測につきゴール 4 つ」という工夫が何を防いでいるのかを追います。
