3. 生成と計画

NWM がふつうの映像生成モデルと決定的に違うのはここです —— 生成された映像は人に見せるためではなく、行動を選ぶために作られます。 2 つの生成モードと、その上に載る Cross-Entropy Method による計画を、コードで追います。

2 つの生成モード

概要編で見たとおり、行動は Eq. (2) の総和で合成できます。 この性質から、まったく同じモデルを 2 通りに使えるようになります。

生成の中核 — model_forward_wrapper

isolated_nwm_infer.py L65–89 GitHub ↗
@torch.no_grad()
def model_forward_wrapper(all_models, curr_obs, curr_delta, num_timesteps, latent_size, device, num_cond, num_goals=1, rel_t=None, progress=False):
    model, diffusion, vae = all_models
    x = curr_obs.to(device)
    y = curr_delta.to(device)

    with torch.amp.autocast('cuda', enabled=True, dtype=torch.bfloat16):
        B, T = x.shape[:2]

        if rel_t is None:
            rel_t = (torch.ones(B)* (1. / 128.)).to(device)
            rel_t *= num_timesteps

        x = x.flatten(0,1)
        x = vae.encode(x).latent_dist.sample().mul_(0.18215).unflatten(0, (B, T))
        x_cond = x[:, :num_cond].unsqueeze(1).expand(B, num_goals, num_cond, x.shape[2], x.shape[3], x.shape[4]).flatten(0, 1)
        z = torch.randn(B*num_goals, 4, latent_size, latent_size, device=device)
        y = y.flatten(0, 1)
        model_kwargs = dict(y=y, x_cond=x_cond, rel_t=rel_t)
        samples = diffusion.p_sample_loop(
                model.forward, z.shape, z, clip_denoised=False, model_kwargs=model_kwargs, progress=progress, device=device
        )
        samples = vae.decode(samples / 0.18215).sample

        return torch.clip(samples, -1., 1.)

読みどころは 4 点です。

  • rel_t の既定計算 (1/128) * num_timesteps —— num_timesteps は拡散のステップ数ではなくフレーム数です。 学習側の goal_offset / 128(学習編)と同じ正規化を再現しています。 引数名が紛らわしいので注意
  • 純ガウスノイズ z から始める —— 前フレームの潜在を初期値にする「ウォームスタート」はしていません。毎回まっさらから 250 反復です
  • clip_denoised=False —— VAE 潜在は \([-1,1]\) に収まらないので、ピクセル用のクリップを無効化しています
  • VAE の符号化・復号がループの中に入っている —— 自己回帰ロールアウトはピクセル空間を経由して状態を持ち回ります。 潜在のまま持ち回れば VAE 往復を省けますが、 そうしていないのは「文脈は必ず実画像から作る」という素直な実装を選んだためと読めます

def generate_rollout(args, output_dir, rollout_fps, idxs, all_models, obs_image, gt_image, delta, num_cond, device):
    rollout_stride = args.input_fps // rollout_fps
    gt_image = gt_image[:, rollout_stride-1::rollout_stride]
    delta = delta.unflatten(1, (-1, rollout_stride)).sum(2)
    curr_obs = obs_image.clone().to(device)

    for i in range(gt_image.shape[1]):
        curr_delta = delta[:, i:i+1].to(device)
        if args.gt:
            x_pred_pixels = gt_image[:, i].clone().to(device)
        else:
            x_pred_pixels = model_forward_wrapper(all_models, curr_obs, curr_delta, rollout_stride, args.latent_size, num_cond=num_cond, num_goals=1, device=device)

        curr_obs = torch.cat((curr_obs, x_pred_pixels.unsqueeze(1)), dim=1) # append current prediction
        curr_obs = curr_obs[:, 1:] # remove first observation
        visualize_preds(output_dir, idxs, i, x_pred_pixels)

計画 — エネルギー最小化としての定式化

ここからが NWM の本題です。生成できるようになったモデルを、どうやって行動決定に使うのか。

論文 Eq. (4) — エネルギー関数 $$E(s_0, a_0, \dots, a_{T-1}, s_T) = -S(s_T, s^*) + \sum_{\tau=0}^{T-1} \mathbb{I}(a_\tau \notin \mathcal{A}_{\text{valid}}) + \sum_{\tau=0}^{T-1} \mathbb{I}(s_\tau \notin \mathcal{S}_{\text{safe}})$$ 第 1 項: \(S(s_T, s^*)\) は最終状態とゴールの知覚的類似度。 両方を VAE デコーダで画素に戻し、LPIPS / DreamSim で測ります。
第 2 項: 「左に行ってから右はダメ」のような行動制約。 違反したら大きなペナルティを足すだけの指示関数です。
第 3 項: 「崖のふちを通るな」のような状態制約。

そして解くべき問題(Eq. 5): $$\arg\min_{a_0, \dots, a_{T-1}} \mathbb{E}_{s}\big[E(s_0, a_0, \dots, a_{T-1}, s_T)\big]$$ 期待値 \(\mathbb{E}_s\) が付いているのは、NWM が確率的だからです —— 同じ行動列でも生成結果は毎回違うので、複数回サンプリングして平均を取ります。
この定式化が持つ 3 つの帰結
  1. 制約は「モデルの外」にある —— 第 2・第 3 項はエネルギーに足されるだけで、\(F_\theta\) には一切触れません。 だから再学習なしで制約を追加できます。これが §1 で挙げた第 1 の限界への回答です
  2. 計算量を後から増やせる —— \(\arg\min\) をどれだけ丁寧に解くかは自由。サンプル数も反復回数も推論時に決められます。 これが第 2 の限界への回答です
  3. 「良さ」の定義を差し替えられる —— LPIPS の代わりに別の指標を入れても、モデルは何も変えなくてよい

Cross-Entropy Method の実装

Eq. (5) は微分できません(NWM を 8 回通した先の LPIPS を行動で微分するのは非現実的)。 そこで微分不要の集団ベース最適化である CEM が使われます。

ヨーの扱い — calculate_delta_yaw が何をしているか

misc.py L188–196 GitHub ↗
def calculate_delta_yaw(unnorm_actions):
    x = unnorm_actions[..., 0]
    y = unnorm_actions[..., 1]

    yaw = torch.atan2(y, x).unsqueeze(-1)
    delta_yaw = torch.cat((torch.zeros(yaw.shape[0], 1, yaw.shape[2]).to(yaw.device), yaw), dim=1)
    delta_yaw = delta_yaw[:, 1:, :] - delta_yaw[:, :-1, :]

    return delta_yaw

等速直線なので各ステップの atan2(Δy, Δx) はすべて同じ値です。 先頭にゼロを詰めてから差分を取るので、結果は 「第 1 ステップで進行方向へ回頭し、以降は回頭しない」という列になります。 そこへ deltas[:, -1, -1] += sample[:, -1] * np.pi で最終ステップの回頭が上乗せされる —— 論文の “applying the yaw rotation at the final step” がこの 1 行です。

なお atan2 に渡しているのが非正規化した Δx, Δy である点は正しい実装です。 正規化空間(min=[-2.5,-4], max=[5,4] による \([-1,1]\) 写像)では x 軸と y 軸のスケールが違うため、そのまま atan2 を取ると角度が歪みます。 一方でモデルに渡す並進量は正規化済みのままです —— 学習時と同じ空間だからです。この使い分けは意図的で、正しい。

論文とコードの照合 — CEM ハイパーパラメータ planning_eval.py の argparse 既定値は num_samples=10, topk=5, opt_steps=15, num_repeat_eval=1 で、 論文 Appendix 7(N=120、1 反復、M 回平均)とはまったく違います。

ただし README の評価コマンドは論文と一致します —— --num_samples 120 --topk 5 --opt_steps 1 --num_repeat_eval 3。 つまり argparse の既定値は開発中の名残で、再現には README のコマンドを使うべきです。

また config/data_hyperparams_plan.yaml の値 (RECON なら mu: [-0.1, 0, 0], var_scale: [0.02, 0.1, 0.1])は 論文 §8.2 の記述(RECON: \((\mu_{\Delta x}, \sigma^2_{\Delta x}) = (-0.1, 0.02)\)、 \(\sigma^2_{\Delta y} = \sigma^2_\phi = 0.1\))と数値としては一致しますが、 コードはこの値を分散ではなく標準偏差として使っています (torch.randn(...) * sigma + mu)。論文の \(\sigma^2 = 0.1\) を字義どおり取れば 標準偏差は約 0.316 で、実際の探索幅は 3 倍以上違うことになります。
最終ロールアウトでのヨーの単位 CEM ループ内では deltas[:, -1, -1] += sample[:, -1] * np.pi と、 サンプル値に π を掛けてラジアンにしています。 その後 mu[traj] = topk_action.mean(dim=0) で更新される mu の第 3 成分は、 すでに π が掛かったラジアン値です。 ところが最終ロールアウト(L283)では、同じ mu[:, -1] にもう一度 * np.pi を掛けています。

つまり選抜のときに評価した回頭角と、最後に実行される回頭角が π 倍ずれます。 ATE / RPE は並進成分のみから計算される(actions_to_traj が姿勢を単位クォータニオンで埋める)ため Table 2 / Table 7 の数値には影響しませんが、 最終予測画像と yaw_diff_norm は影響を受けます。 論文の Table 3(制約付き計画の \(\delta\phi\))を読むときは、この点を頭に置いておくとよさそうです。

制約付き計画 — モデルを触らずに条件を足す

論文 §4.4 の「制約付き計画」は、驚くほど単純な方法で実現されています —— 行動の一部をゼロで固定するだけです。

制約(論文 Table 3)やること実装結果(無制約との差)
forward first 5 ステップ前進 → 3 ステップ回頭 最初の 5 手は u = (Δx, 0)、 残り 3 手は u = (0, Δy) δu +0.36 / δφ +0.61
left-right first 3 ステップ回頭 → 前進 最初の 3 手は前進成分をゼロに固定し、残りを CEM で最適化 δu −0.03 / δφ +0.20
straight then forward 3 ステップ直進 → 前進 同上のパターンで別の成分を固定 δu +0.08 / δφ +0.22
この実験が示していること δu / δφ は「無制約で計画したときの終端位置・姿勢からのズレ」です。 どの制約でもすべて満たされたうえで、ズレは小さい —— つまり「制約を守ると目的地に着けなくなる」わけではない、ということを示しています。

方策ベースの手法だと、こうした制約は報酬設計をやり直して再学習するのが普通です。 NWM では探索する行動集合を絞るだけで、モデルは 1 パラメータも変わりません。

外部方策のランキング — NWM を「採点係」として使う

もう 1 つの使い方は、既存の方策 \(\Pi(a \mid s_0, s^*)\) と組ませることです。

  1. NoMaD に、過去の観測とゴール画像を与えて \(n \in \{16, 32\}\) 本の軌道を生成させる
  2. それぞれを NWM でロールアウトする
  3. 最終フレームとゴール画像の LPIPS で採点し、最小の 1 本を採用する

CEM との違いは、候補の出どころが最適化ではなく学習済み方策という点だけです。 エネルギー関数(Eq. 4)は同じものを使います。

この実験の再現コードは公開されていません planning_eval.py には CEM の実装しかなく、NoMaD の推論を呼ぶ経路はありません。 唯一の痕跡は --num_samples のヘルプ文字列 ("num nomad samples to predict")と、コメントアウトされた # self.exp_eval = f'{self.exp}_nomad_eval' です。 論文 Table 2 / Table 7 の “NWM + NoMaD” 行を再現するには、 visualnav-transformer から NoMaD を呼んで候補を差し込む部分を自分で書く必要があります。

実時間で動くのか — 推論コストの現実

論文 §8.2 “Real-World Applicability” は、この点を正面から扱っています。 NVIDIA RTX 6000 Ada 上で、4 秒の軌道 1 本をシミュレートする時間:

構成実行時間(秒)何をしたか
NWM そのまま30.316 状態 × 250 デノイズステップ
+ Time Skip14.7隣接する行動 2 つを Eq. (2) で合成し、16 状態を 8 状態に。 「ナビゲーション性能は劣化しない」と報告
+ 蒸留0.4デノイズを 250 → 6 ステップに蒸留(FastVideo の DiT 向け実装)。 「軽微な視覚品質の低下」
+ 4-bit 量子化0.1(推定)未実施。先行研究から約 4 倍を見込む

軌道どうしの評価は並列化できるので、この 1 本あたりの時間が実時間性を決めます。 論文の結論は “existing solutions can already enable real-time applications of NWM at 2-10 Hz”。 30 秒が 0.4 秒になる —— このうち 75 倍の大部分を稼いでいるのは アーキテクチャではなく拡散ステップ数の削減である点は、素直に押さえておくべきでしょう。

計画 1 回にかかる本当のコスト 論文の設定(120 サンプル × 8 ステップ × 3 回平均)で、CDiT の順伝播回数は $$120 \times 8 \times 3 \times 250 = 720{,}000 \text{ 回}$$ これを 8 GPU に分けて回します。 アーキテクチャ編で見た 「1 回の順伝播を軽くする」という設計思想が、 ここで 72 万倍に増幅されて効いてくるわけです。 CDiT が DiT の 4 分の 1 の FLOPs で済むということは、 この計画が 4 分の 1 の時間で終わるということでもあります。

この章のまとめ

生成と計画を 4 点で
  1. 生成モードは 2 つ —— 時間ジャンプ(k 秒ぶんを総和して 1 回)と 自己回帰ロールアウト(1 手ずつ、出力を文脈に戻す)。計画に使うのは後者
  2. 計画はエネルギー最小化。第 1 項がゴールとの知覚的距離、第 2・第 3 項が制約。 制約はモデルの外側にあるので、再学習が要らない
  3. CEM が探索するのはたった 3 次元(Δx, Δy, φ)。 軌道を直線と仮定し、進行方向のヨーは atan2 で自動決定、回頭は最終ステップにまとめる
  4. コストは順伝播 72 万回。だから「1 回を軽くする」CDiT の設計が決定的に効く。 蒸留まで入れれば 2〜10 Hz の実時間動作が視野に入る

次章では、この一連の仕掛けが実際にどれだけ効いたのかを、 評価指標の設計から実験結果の細部まで追います。
