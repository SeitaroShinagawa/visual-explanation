1. アーキテクチャ

統一モデルの設計は「どこを共有し、どこを分けるか」に尽きます。 本作は共有する部分(系列・注意機構)を最大化し、分ける部分(FFN)を 固定の 2 分割から、学習されたルーティングへと進めていきます。

土台 — Transfusion からの 2 つの差分

バックボーンはデコーダ専用 Transformer で、Transfusion(Zhou+, 2025)に倣っています。 ただし論文は 2 点の変更を明記します。

Transfusion本作理由(論文の記述)
視覚の入出力射影 U-Net 単純な線形射影層 明示的な理由は書かれていないが、 エンコーダ非依存(encoder-agnostic)にするための簡素化と読める。 §3 でエンコーダを 7 種類差し替える実験があり、U-Net だと差し替えのたびに設計変更が要る
各層の FFN 共有 FFN モダリティ別 FFN(テキスト用・視覚用の 2 本) Figure 15 で全指標が改善することを確認したうえで既定に採用。 詳細は後述

既定モデルは総パラメータ 2.3B / トークンあたりアクティブ 1.5B。 「総 > アクティブ」になっているのは、モダリティ別 FFN のせいです —— 2 本の FFN のうちトークンごとに 1 本しか動かないため、 パラメータは増えても FLOPs は増えません。

系列フォーマットとハイブリッド注意マスク

テキストと画像は1 本の系列に並べられます。 ただし注意の張り方はモダリティごとに違い、そこが設計の要になります。

論文 §C の記述(そのまま) 系列の作り方: “Text tokens are mapped to vectors via a standard nn.Embedding layer. Visual inputs are mapped to latent patches using a frozen visual encoder and flattened into 1D sequences. We enclose each image or video frame with beginning-of-image (<BOI>) and end-of-image (<EOI>) marker tokens. A video is processed as a series of individually bounded frames.”

注意マスク: “Text tokens apply a standard causal mask. For visual data, we apply a block-wise causal mask: patches within the same image attend bidirectionally, but can only attend causally to text or visual frames that appeared previously.”

視覚表現 — 何をトークンにするか

本作のアーキテクチャはエンコーダ非依存で、凍結した任意のエンコーダを受け付けます。 §3 の実験では 3 つのファミリを比較します(結果は実験編)。

ファミリ具体例解像度 / パッチグリッドアダプタトークン数
生ピクセルRaw Pixel224² / 14×1416×16—256
RAE(意味エンコーダ)SigLIP 2 (既定)224² / 14×1416×16—256
DINOv2-L224² / 14×1416×16—256
WebSSL-L224² / 14×1416×16—256
VAESD-VAE256² / 8×832×32Pix[Un]shuf(2)256
FLUX.1256² / 8×832×32Pix[Un]shuf(2)256

すべて 256 トークンに揃えてあるのが統制実験としての要点です (論文 Table 5: “All encoders produce 256 tokens (16×16 grid) per image”)。 VAE 系だけ 32×32 の潜在が出るので、Pixel[Un]shuffle で 2 倍に畳んで256 に合わせています。 トークン数が揃っていなければ、比較しているのが「表現の質」なのか「計算量」なのか分からなくなります。

RAE(Representation Autoencoder)とは何か 名前は「オートエンコーダ」ですが、学習するわけではありません。 意味エンコーダ(SigLIP 2 など)の潜在空間を、そのまま拡散の作業場として使うという考え方です。

従来の常識では、生成には VAE 潜在が必要でした —— 低次元で、画素に戻せるからです。 意味エンコーダの潜在は高次元で、しかも画素に戻す復号器がない。 RAE(Zheng+, 2026 / Tong+, 2026)は、その潜在空間に対する既製の復号器を用意することで、 「意味エンコーダの潜在の上で拡散を回し、最後に画素へ戻す」を可能にしました。 本作はその成果を借りて、理解と生成で同じ 1 つのエンコーダを使うという簡素化に踏み切ります。

論文の言い方: “we simplify our design by using a single visual encoder for both understanding and generation.” BAGEL の二重エンコーダとは正反対の判断です。

容量をどう分けるか — 4 段のはしご

統一モデルの設計論争の核心は「テキストと画像で、モデルの容量をどう分け合うか」です。 本作はこれを 4 段階のはしごとして整理し、実際に全段を学習して比較します(§6.3)。

MoE の設計空間 — 3 つのつまみ

MoE を採用すると決めた後、設計者には 3 つのつまみが残ります。 §6.1 はそれぞれを独立に振って最良点を探します (特記なき限り、DCLM テキスト 50% / Shutterstock 画像 50% で 57B トークン学習)。

つまみ 1: 粒度(granularity)

粒度 G の定義(論文 §6.1) $$G = \frac{4\, d_{\text{model}}}{d_{\text{expert}}}$$ アクティブな計算量を固定したまま、\(G\) を上げるとエキスパートは小さく・数は多くなります。

つまみ 2: スパース性(総エキスパート数)

\(G = 16\) に固定し、アクティブな予算(16 エキスパート・隠れ次元 512)を据え置いたまま、 総エキスパート数を 32 → 1008 に増やします。アクティブ比率は 50% から 1.6% まで下がります。

結果(Figure 21・Figure 24) 両モダリティとも、総エキスパート数を増やすほど一貫して良くなります —— テキスト PPL は下がり、拡散損失は下がり、GenEval は上がる。しかも計算量は固定のまま。 「MoE が言語で効くことは知られていたが、統一マルチモーダル事前学習にも素直に延長できる」というのが結論です。

ただし視覚表現によって差が出ます(Figure 24)。 RAE(SigLIP 2)ではテキスト損失も拡散損失も伸び続けるのに対し、 VAE(FLUX.1)では拡散損失が飽和します。 論文はこれを “semantic representations scale better with sparsity” と表現しています —— §3 の「RAE が VAE に勝つ」という結論が、容量を増やしたときの伸びしろでも再確認された形です。

つまみ 3: 共有エキスパート

DeepSeek-MoE 系で使われる「常時アクティブな共有エキスパート」を置くべきか。 3 通りを比較します(総 256 個・アクティブ 16 個)。

共有なし(素の top-16)14.8027.390.4840.360

差は小さいものの全指標でモダリティ別共有が最良です。 論文はここから “suggesting different modalities have distinct capacity needs” という読みを引き出し、次節の分析へつなげます。

創発するエキスパート特化

MoE を採用した以上、ルータが実際に何を学んだのかを見る必要があります。 分析対象は 13.5B 総 / 1.5B アクティブ、G=16、256 エキスパート、SigLIP 2、x 予測で 1T トークン(テキスト 50% / 動画 25% / 画像テキスト 22.5% / 行動 2.5%)学習したモデルです。

特化スコアの定義(論文 §F.7) エキスパート \(e_i\) とモダリティ \(m\) について、選択率 \(R^{(i)}_m = C^{(i)}_m / (N_m \times k)\) を測り、 $$S_i = \frac{R^{(i)}_{\text{text}} - R^{(i)}_{\text{image}}}{R^{(i)}_{\text{text}} + R^{(i)}_{\text{image}}}$$ \(S_i > 0.5\) をテキスト特化、\(S_i < -0.5\) を視覚特化、その間をマルチモーダルと分類します。

この章のまとめ

アーキテクチャを 4 点で
  1. 共有できるものはすべて共有する —— 系列も self-attention も 1 つ。 分かれるのは注意マスクの可視性・FFN・出口のヘッドだけ
  2. 視覚表現は 1 つで足りる —— SigLIP 2 の潜在の上で直接拡散を回す(RAE)。 比較のためエンコーダはすべて 256 トークンに揃えてある
  3. 容量分離は「学習させる」のが最良 —— 共有 FFN → モダリティ別 FFN → MoT → MoE の 4 段で、MoE が全指標で勝つ
  4. MoE の設定は G=16・高スパース性・モダリティ別共有エキスパート。 そしてモダリティ特化は設計しなくても創発する

次章では、この 1 つのモデルの中で性質のまったく違う 2 つの目的関数がどう同居するのか、 そして推論時にどうやってモダリティを切り替えるのかを見ます。
