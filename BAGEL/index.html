BAGEL 図解

テキストも画像も 1 つの Transformer が生成する統一マルチモーダル基盤モデル「BAGEL」 (Emerging Properties in Unified Multimodal Pretraining, ByteDance Seed, 2025)。 外部の拡散モデルを持たず、LLM 自身が Rectified Flow のデノイザになるという 設計を、実装コードの引用とアニメーション図解で読み解きます。

BAGEL とは

BAGEL (Deng+, 2025)は ByteDance Seed による 7B activated / 14B total パラメータの統一マルチモーダル基盤モデルです。 公式 README はその立ち位置をこう説明しています。

公式 README より “We present BAGEL, an open-source multimodal foundation model with 7B active parameters (14B total) trained on large-scale interleaved multimodal data. BAGEL outperforms the current top-tier open-source VLMs like Qwen2.5-VL and InternVL-2.5 on standard multimodal understanding leaderboards, and delivers text-to-image quality that is competitive with strong specialist generators such as SD3.” (README.md)

本シリーズでこれまで扱った NExT-GPT と CoDi-2 は、どちらも 「凍結した LLM と凍結した拡散モデルを、小さな射影層で接着する」という構図でした。 BAGEL はそこから根本的に離れます。

BAGEL の一行要約 BAGEL には外部の拡散モデル(UNet / DiT)が存在しません。 画像を作るとき、ノイズを除去しているのは LLM 本体の Transformer 層そのものです。 LLM は「拡散モデルに渡すプロンプト」も「条件ベクトル」も書きません。 VAE 潜在パッチを自分の隠れ状態として抱え込み、その速度場 \(v\) を直接出力します。

そのために BAGEL が導入したのが、次の 3 点です。

  • Mixture-of-Transformer-Experts(MoT) — 1 本のトークン列の上で、理解用エキスパートと生成用エキスパートが self-attention だけを共有しながら、重みは完全に別々に持つ
  • 二重の視覚エンコーダ — 同じ画像を SigLIP ViT(意味レベル)と VAE(ピクセルレベル)の両方で符号化して列に並べる
  • Generalized Causal Attention — テキストは causal、画像トークンは双方向、そしてノイズを載せた生成対象だけは他から見えないという 3 種類の可視性を、1 枚の attention マスクで表現する
学習目的は驚くほど単純です 公開コードの損失はたった 2 本、しかも足し算するだけです。 $$\mathcal{L} \;=\; \lambda_{\text{ce}}\,\mathcal{L}_{\text{CE}} \;+\; \lambda_{\text{mse}}\,\mathcal{L}_{\text{MSE}}$$ \(\mathcal{L}_{\text{CE}}\) は普通の次トークン予測、 \(\mathcal{L}_{\text{MSE}}\) は Rectified Flow の速度場回帰です。 公開コードの既定値は ce_weight = mse_weight = 1.0 ですが、 論文の学習レシピ(Table 3)では CE : MSE = 0.25 : 1 が使われています。 この非対称な重みには理由があり、論文 §4.2 のアブレーションで 「学習率を上げると MSE は速く下がるが CE は悪化する」という綱引きが観測されたため、 2 つの目的関数に別々の重みを割り当てて折り合いをつけたと説明されています。

いずれにせよ、NExT-GPT の「整合損失+拡散損失+CE」や CoDi-2 の 3 項構成と違い、 接着のための損失(モダリティ整合項)が 1 つも要りません —— 接着すべき外部モデルがそもそも無いからです。 対応は学習編で 1 行ずつ突き合わせます。

全体アーキテクチャ

データの流れは 「テキストと画像を 1 本のトークン列に詰める → MoT Transformer が読む → 出口が 2 つに分かれる(語彙 or VAE 潜在)→ 画像側はフローの積分を繰り返す」 です(図は自動でループ再生されます)。

系譜 — 「接着」から「統合」へ

本シリーズの 3 モデルを並べると、 LLM と画像生成器の距離がどんどん縮まっていく流れがはっきり見えます。 実はこの流れは、論文 §2.1 が統一モデルの設計空間を 3 つに分類したものと、そのまま対応します。

論文の分類(§2.1)やり方本シリーズの該当モデル
Quantized AR 画像を離散トークンに量子化し、テキストと同じ Next-Token-Prediction で生成する —(Chameleon / Emu3 / Janus 系)
External Diffuser LLM が潜在トークン列を自己回帰生成し、それを「意味的な条件」として外部の拡散モデルに渡す NExT-GPT・CoDi-2
Integrated Transformer LLM と拡散モデルを 1 つの Transformer に統合し、両者を切り替えながら動かす BAGEL
論文が External Diffuser 方式に下す評価(§2.1) 著者たちは、NExT-GPT や CoDi-2 が採る方式の長所を認めた上で、その限界をこう述べています —— “Its primary drawback, however, is the compression of the LLM context into a relatively small number of latent tokens. This introduces an explicit bottleneck between understanding and generation modules, risking substantial information loss—particularly in long-context multimodal reasoning. Such a constraint might contradict the scaling philosophy of large foundational models.”

つまり「77×1024」や「1×1024」という細さそのものが問題だ、という診断です。 そして Integrated Transformer を選ぶ理由を “maintaining a bottleneck-free context throughout all transformer blocks” と述べています。本シリーズを 3 作続けて読むと、この一文の重みが実感できます。

ひとことで言うと NExT-GPT と CoDi-2 は「LLM に、生成器への注文書を書かせる」方式。 BAGEL は「LLM に、絵の具を直接触らせる」方式です。 前者は既存の強い生成器をそのまま活かせるかわりに注文書の帯域で情報が絞られ、 後者は帯域制限が消えるかわりに、生成能力を一から学習し直す必要があります (だから 5T トークン規模の事前学習が要ります)。

なぜ「Emerging Properties」なのか

論文のタイトルにもなっている emerging properties とは何を指すのか。 論文は、大規模言語モデルの文脈で使われる定義をそのまま持ち込みます。

論文 §6 の定義 “An ability is emerging if it is not present in earlier training stages but is present in later pre-trainings.”

重要なのは、この立ち上がりが損失曲線には現れないという点です。 論文は「loss curves do not explicitly signal the emergence of new capabilities」と述べ、 だからこそ過去のチェックポイントを掘り起こしてベンチマークを回し直すという方法を採っています。

その結果が、BAGEL でもっとも面白い数字です。 「ピーク性能の 85% に到達するまでに何トークン必要だったか」を能力ごとに測ると、 タスクの複雑さに応じてきれいに階段状に並びます。

能力指標85% 到達に要したトークン
マルチモーダル理解VLM ベンチマーク平均約 0.18T
画像生成GenEval約 0.68T
画像編集GEdit-Bench約 2.64T
知的な編集
(複雑な推論を要する編集)		IntelligentBench約 3.61T

理解と生成が先に立ち上がり、両者を組み合わせる編集がその後、 そして推論を要する編集が最後に来る。 とくに IntelligentBench のスコアは、3T トークンを超えたあたりから急に伸びはじめ、 学習後半で 15 から 45 へ 3 倍になったと報告されています。 それ以前のモデルは「よく分からないので入力画像をほぼそのまま返す」という 逃げの挙動を見せていた、という観察も添えられています。

二重エンコーダの効き方も、ここで数字になる 論文は「ViT トークンを外す」アブレーションも報告しています。 結果はGEdit-Bench(素直な編集)にはほとんど影響しないのに、 Intelligent Edit では 16% 低下。

つまり VAE のピクセル情報だけでも「言われた通りに塗り替える」ことはできるが、 「何を意味する編集なのか」を考えるには意味レベルの視覚情報が要る、ということです。 アーキテクチャ編で見る二重エンコーダの設計は、 この一点のために存在していると言ってもよさそうです。

学習と生成の見どころ(ダイジェスト)

学習: 1 枚のシーケンスに「読む画像」と「描く画像」が同居する

画像編集のサンプルでは、入力画像 1 枚に対して 3 種類のトークン列が作られます。

  1. clean VAE トークン — 条件として与えるピクセルレベルの情報
  2. ViT トークン — 同じ画像の意味レベルの情報
  3. noised VAE トークン — 生成対象。Rectified Flow の \(x_t\) が入り、ここだけ MSE 損失がかかる

この 3 種が 1 本の列に並び、③ だけが他のトークンから見えないように attention マスクが組まれます(attn_modes の 'noise')。 「答えを見ながら答えを書く」状態を、モデル構造ではなくマスクで防いでいるわけです。 詳細は学習編へ。

生成: 50 回 Transformer を呼び直すが、前置きは 1 回しか読まない

画像生成は x ← x − v·Δt を 50 回まわす ODE の積分です。 毎ステップ 7B の Transformer を通しますが、 プロンプトや参照画像の KV キャッシュは最初に 1 回作ってから使い回され、 再計算されるのは潜在トークンの部分だけです。 さらに CFG のために文脈を 3 通り(通常 / テキスト無し / 画像無し)用意して並走させます。 詳細は生成編へ。
