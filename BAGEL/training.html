2. 学習プロセス

1 枚のシーケンスの中でテキストの CE 損失と 画像の Rectified Flow MSE 損失が同時に計算される仕組みを、 データの組み立てから損失の合成まで追いかけます。

学習の全体像 — 4 つのステージ

論文は BAGEL の学習を 4 段階に分けています。 「まず言葉と絵を同じ土俵に載せ、次に大量に読ませ、解像度を上げ、最後に磨く」という順序です。

出典について ステージ構成とトークン数は論文側の記述です(本解説の作業環境では PDF を直接取得できず、 公式 README・TRAIN.md と複数の二次情報で一致が確認できた範囲に限って記載しています)。 以降のコードの説明はすべて、クローンした コミット a2fa77d の実ファイルからの引用です。

データがシーケンスになるまで

BAGEL のデータパイプラインは 2 段構えです。

  1. データセット側が sequence_plan という「設計図」を作る (どの順で、何を、損失ありで置くか)
  2. パッカー側(PackedDataset.pack_sequence)が設計図を読んで、 実際のトークン列・位置 ID・損失インデックス・attention モードを組み立てる

設計図の作り方 — 1 枚の画像から最大 3 種類のトークン

interleave 系データセットの基底クラスにある _add_image が、この設計の核心です。 3 つのフラグ(need_loss / need_vae / need_vit)が独立していて、 複数立てると同じ画像が列に複数回登場します。

注目: enable_cfg が ① だけ 0 になっている enable_cfg は「CFG のためにこのトークンをランダムに落としてよいか」のフラグです。 生成対象(①)は落としてはいけないので 0 が固定で書かれています。 条件として置かれる ② ③ だけがドロップアウトの対象になります。 後述のとおり、この 1 行が推論時の二重 CFG を可能にしています。

float('-inf') という書き方が効いている 条件画像の時刻に -inf を入れておくと、モデル側で torch.sigmoid(-inf) = 0、 すなわちノイズ混合率 0 = 完全にきれいな潜在になります。 「ノイズを載せない」を別フラグではなく時刻の値として表現しているので、 コード上は条件画像も生成対象も同じ 1 本の式を通ります。

損失 ① — Rectified Flow の MSE

モデルの forward に入ると、時刻からノイズ混合、そして速度場の教師まで一気に計算されます。

modeling/bagel/bagel.py L181–197 — ノイズを載せる GitHub ↗
        if self.config.visual_gen:
            p = self.latent_patch_size
            packed_latent = []
            for latent, (h, w) in zip(padded_latent, patchified_vae_latent_shapes):
                latent = latent[:, :h * p, :w * p].reshape(self.latent_channel, h, p, w, p)
                latent = torch.einsum("chpwq->hwpqc", latent).reshape(-1, p * p * self.latent_channel)
                packed_latent.append(latent)
            packed_latent_clean = torch.cat(packed_latent, dim=0)          # x_0(きれいな潜在)

            noise = torch.randn_like(packed_latent_clean)                  # x_1(純ノイズ)
            packed_timesteps = torch.sigmoid(packed_timesteps)             # ★ logit-normal な t
            packed_timesteps = self.timestep_shift * packed_timesteps / (1 + (self.timestep_shift - 1) * packed_timesteps)
            packed_latent = (1 - packed_timesteps[:, None]) * packed_latent_clean + packed_timesteps[:, None] * noise
            packed_timestep_embeds = self.time_embedder(packed_timesteps)
            latent_token_pos_emb = self.latent_pos_embed(packed_latent_position_ids)
            packed_latent = self.vae2llm(packed_latent) + packed_timestep_embeds + latent_token_pos_emb
            packed_sequence[packed_vae_token_indexes] = packed_latent
modeling/bagel/bagel.py L217–229 — 損失を取る GitHub ↗
        mse = None

数式に直すと きれいな潜在を \(x_0\)、標準正規ノイズを \(x_1\) とし、時刻 \(t\in[0,1]\) で直線補間します。 $$x_t \;=\; (1-t)\,x_0 \;+\; t\,x_1$$ この直線を時刻で微分すれば、速度場は定数 \(x_1 - x_0\) になります。 $$v_t \;=\; \frac{dx_t}{dt} \;=\; x_1 - x_0$$ モデルはこれを当てにいきます。 $$\mathcal{L}_{\text{MSE}} \;=\; \mathbb{E}_{t,\,x_1}\Big[\big\|\,v_\theta(x_t,\,t,\,c)\;-\;(x_1 - x_0)\,\big\|^2\Big]$$ ここで \(c\) は同じシーケンス上の全ての先行トークン(テキスト・ViT・clean VAE)です。 拡散モデルのように「cross-attention で注入される条件」ではなく、 self-attention の相手として直接そこに居る、という点が BAGEL の本質です。

時刻は \(t' \sim \mathcal{N}(0,1)\) を引いて \(t = \sigma(t')\) とする logit-normal サンプリング(SD3 などと同じ流儀)。 \(t\approx 0.5\) 付近が厚くサンプルされ、両端は薄くなります。
⚠️ has_mse の非対称性に注意 packed_mse_preds は mse_loss_indexes(データ側が決めた損失位置)で切り出され、 target は has_mse = packed_timesteps > 0(時刻が正のトークン)で切り出されます。 切り出し方が違う 2 つのテンソルを引き算しているわけです。 両者が一致するのは「損失位置 ⟺ 時刻が正」がデータ生成側で保証されているからで、 pack_sequence が loss == 1 のときだけ np.random.randn() を、 そうでなければ -inf(→ sigmoid で 0)を入れているという不変条件に依存しています。 ここを崩すデータセットを自作すると静かにずれます。

data/data_utils.py L168–177 — サンプル長による重み GitHub ↗
def len2weight(x, loss_reduction='square'):
    if x == 0:
        return x
    if loss_reduction == 'token':
        return 1                    # トークン平均(長い応答が支配的になる)
    if loss_reduction == 'sample':
        return 1 / x                # サンプル平均(短い応答が支配的になる)
    if loss_reduction == 'square':
        return 1 / (x ** 0.5)       # ★ 既定: その中間
    raise NotImplementedError(loss_reduction)

長い応答も短い応答も公平に扱うため、\(1/\sqrt{L}\) で重み付けします (ce_loss_reweighting=True のときだけ有効。既定は False)。

数式コード備考
\(\mathcal{L}_{\text{CE}}\) F.cross_entropy(lm_head(h[ce_idx]), labels) テキストと(理屈上は)特殊トークンの予測
\(\mathcal{L}_{\text{MSE}}\) (llm2vae(h[mse_idx]) - (noise - clean))**2 チャネル方向に平均 → トークン方向に平均
\(\lambda_{\text{ce}},\ \lambda_{\text{mse}}\) ce_weight, mse_weight どちらも既定 1.0
正規化 * world_size / total_*_tokens GPU 間でトークン数が不均一でも、全体を 1 バッチとみなして平均が取れる
「整合損失」が要らない NExT-GPT は \(\|h_{\text{LLM}} - E_{\text{text}}(c)\|^2\)、CoDi-2 は \(\alpha\,\mathrm{MSE}(c_{\text{MLLM}}, C_x(x))\) という接着のための損失を持っていました。 外部の生成器が期待する空間に、LLM の出力を「合わせにいく」項です。
BAGEL にはこれが1 つもありません。合わせるべき相手が居ないからです。 MSE 損失は「生成器への入力を模倣する」ためではなく、 生成そのもののための損失になっています。

CFG のためのドロップアウト

推論時に classifier-free guidance を使うには、 学習時に「条件が無い状態」を経験させておく必要があります。 BAGEL は条件の種類ごとに独立した確率を持ちます。

引数既定値落とすもの推論時の対応物
text_cond_dropout_prob0.1テキストブロックを丸ごとスキップcfg_text_scale
vae_cond_dropout_prob0.3条件用 clean VAE ブロックをスキップcfg_img_scale
vit_cond_dropout_prob0.3ViT ブロックをスキップ

画像条件の方が落とす確率が高い(0.3)のは、 編集タスクで「元画像を無視した生成」も同じくらい経験させたいからだと読めます。 実装では単に continue でブロックを列から外すだけですが、 curr_rope_id += 1 だけは実行して位置 ID は進めます —— 落としても後続の位置がずれない、という配慮です。

動画と Diffusion Forcing

複数フレームを扱う場合、_add_video がフレームごとに項目を作りますが、 1 つの split にまとめられます(先頭が split_start、末尾が split_end)。

data/interleave_datasets/interleave_t2i_dataset.py L88–103(抜粋) GitHub ↗
    def _add_video(self, data, frames, frame_indexes, need_loss, need_vae, enable_cfg=True):
        assert int(need_loss) + int(need_vae) == 1
        if need_loss:
            for idx, (image, frame_idx) in enumerate(zip(frames, frame_indexes)):
                current_sequence_plan = {
                    'type': 'vae_image', 'enable_cfg': 0, 'loss': 1, ...
                    'split_start': idx == 0,
                    'split_end': idx == len(frames) - 1,
                }
                if idx < len(frame_indexes) - 1:
                    current_sequence_plan['frame_delta'] = frame_indexes[idx + 1] - frame_idx
⚠️ コードを読むと分かる 2 つの副作用 ①動画 split の attention モードは 'noise' ではなく 'full' になります。 attn_modes.append は split_start のときだけ実行され、 その先頭フレームには frame_delta が付いているため、 if item['loss'] == 1 and 'frame_delta' not in item.keys() の条件を外れるからです。 結果、ノイズ入りのフレームが後続フレームから見える状態になります —— これは論文が言う diffusion forcing(先行フレームのノイジーな表現を条件に次を予測する)そのものです。

②同じ split 内のフレームは同じ時刻 \(t\) を共有します。 timestep = np.random.randn() が split_start のときだけ実行され、 2 フレーム目以降は直前の値を使い回すためです。 「フレームごとに独立なノイズレベル」を期待して読むと食い違うので、 自前の動画データを足すときはここを確認してください。

また frame_delta は RoPE の位置 ID を実際のフレーム間隔だけ進めるのに使われます (curr_rope_id += item['frame_delta'])。 飛ばしてサンプリングしたフレーム列でも、時間的な距離が位置符号に反映されます。

シーケンスパッキング — バッチの正体

BAGEL の「バッチ」は、いわゆる (B, L, D) のテンソルではありません。 複数サンプルを 1 本に連結した長い列 1 本で、 サンプル境界は sample_lens と attention マスクの sample_mask が守ります。

⚠️ 公開データコードでは使われていないフック sequence_plan には special_token_loss / special_token_label という項目があり、 パッカー側は<|im_end|> や <|vision_end|> の位置にも CE 損失を置けるように書かれています。 これは「いま画像を出すべきか、テキストを続けるべきか」をモデル自身に学ばせるための仕掛けに見えますが、 公開されている 4 つのデータセット実装ではすべて special_token_loss: 0 固定で、 実際には一度も有効になりません。 公開コードの推論側も、画像を出すかどうかは呼び出し側が決める設計(interleave_inference の understanding_output フラグ)になっており、両者は整合しています。

学習インフラまわり(参考)

  • FSDP — HYBRID_SHARD が既定。ノード内シャード + ノード間レプリカ
  • EMA — 減衰 0.9999 のモデル平均を別途保持。fine-tuning では --finetune-from-ema True で EMA 側から再開できる
  • bf16 autocast — VAE のエンコードは torch.no_grad() の中で毎ステップ実行 (潜在をキャッシュせず、その場で計算する)
  • FlexAttention — use_flex=True のとき、疎ブロックマスクを create_block_mask(..., BLOCK_SIZE=128, _compile=True) でコンパイルして使う
  • 凍結フラグ — freeze_llm / freeze_vit / freeze_vae は 既定で False / False / True。さらに freeze_und を立てると、 MoT の理解側だけを detach() して生成側だけを学習することができる (PackedAttentionMoT.forward_train の中に if self.config.freeze_und が散在している)
