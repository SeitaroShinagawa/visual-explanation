3. 生成プロセス

「犬の画像を見せて」と頼まれた NExT-GPT の中で何が起きるのか。 generate() の実装を、トークン生成から拡散モデル呼び出しまで一気に追跡します。

生成の全体タイムライン

推論時の処理は大きく 5 ステップです。まずアニメーションで流れを掴んでください。

入口: predict.py — プロンプト構築とシグナルトークン ID の解決

エントリポイント predict.py は会話テンプレート(llava_v1)でプロンプトを組み立て、 シグナルトークンの語彙 ID をトークナイザから引いてから model.generate を呼びます。 この ID リストが後段の「検出」の照合キーになります。

predict.py L154–168(抜粋) GitHub ↗
image_signal_token_indices = [self.tokenizer(f"<image_{i:02d}>").input_ids for i in range(self.model_config.n_img_tokens)]
video_signal_token_indices = [self.tokenizer(f"<video_{i:02d}>").input_ids for i in range(self.model_config.n_vid_tokens)]
audio_signal_token_indices = [self.tokenizer(f"<audio_{i:02d}>").input_ids for i in range(self.model_config.n_aud_tokens)]

with torch.inference_mode():
    output = self.model.generate(
        input_ids=input_ids,
        image_signal_token_indices=image_signal_token_indices,
        video_signal_token_indices=video_signal_token_indices,
        audio_signal_token_indices=audio_signal_token_indices,
        **generation_args.__dict__
    )
各 ID が「ペア」なのはなぜ? tokenizer("<image_00>").input_ids は BOS トークン付きの [1, 32000] のような 2 要素リストを返します。以降のコードで image_signal_token_indices[0][1] と [1] 添字が頻出するのは、 ペアの 2 番目=実際のトークン ID を取り出しているためです。

Step 1–2: 埋め込み化と自己回帰生成

generate() は内部で _get_generation() を呼び、 学習時と同じ prepare_inputs_labels_for_multimodal (アーキテクチャ編参照)で入力を埋め込み列にしてから、 HuggingFace 標準の generate に委譲します。 ポイントは output_hidden_states=True と return_dict_in_generate=True — 後で隠れ状態を回収するための指定です。

nextgpt/model/language_model/nextgpt_llama.py L602–615(抜粋) GitHub ↗
outputs = super().generate(
    inputs_embeds=inputs_embeds,
    max_new_tokens=max_new_tokens,
    top_p=top_p,
    temperature=temperature,
    stopping_criteria=stopping_criteria,
    output_hidden_states=output_hidden_states,   # ← 全ステップの隠れ状態を保持
    return_dict_in_generate=True,
    output_attentions=True,
    **kwargs
)

生成が終わると、各ステップの指定層(layer_idx、既定 −1 = 最終層)の隠れ状態を 時間方向に連結して 1 本のテンソルにします。

nextgpt/model/language_model/nextgpt_llama.py L677–681(抜粋) GitHub ↗
layer_idx = getattr(self.config, "layer_idx", -1)
hidden_embedding = [x[layer_idx] for x in outputs.hidden_states[1:]]  # 生成ステップごとの最終層
hidden_embedding = torch.cat(hidden_embedding, dim=1)                 # (1, 生成長, 4096)

Step 3: シグナルトークンの検出 — 生成するか、しないか

生成されたトークン ID 列から、各モダリティの先頭シグナルトークン (<image_00> 等)の出現位置を探します。1 つも見つからなければ テキスト応答だけを返して終了。見つかれば該当モダリティの生成関数へ分岐します。

nextgpt/model/language_model/nextgpt_llama.py L688–728(抜粋・整形) GitHub ↗
# Find up to max_num_rets [IMG] tokens, and their corresponding scores.
all_gen_img_idx = [i for i, x in enumerate(generated_ids[0, :] == image_signal_token_indices[0][1]) if x][:max_num_imgs]
all_gen_vid_idx = [i for i, x in enumerate(generated_ids[0, :] == video_signal_token_indices[0][1]) if x][:max_num_vids]
all_gen_aud_idx = [i for i, x in enumerate(generated_ids[0, :] == audio_signal_token_indices[0][1]) if x][:max_num_auds]

if len(all_gen_img_idx) == 0 and len(all_gen_vid_idx) == 0 and len(all_gen_aud_idx) == 0:
    return return_outputs                      # テキストのみの応答

if len(all_gen_img_idx) > 0:
    img_outputs = self.generate_images(generated_ids, hidden_embedding, all_gen_img_idx,
                                       image_signal_token_indices,
                                       guidance_scale=guidance_scale_for_img,      # 7.5
                                       num_inference_steps=num_inference_steps_for_img)  # 50
    return_outputs['images'] = img_outputs
# videos / audios も同様に分岐

Step 4–5: 隠れ状態の変換と拡散パイプライン呼び出し

generate_images では、検出位置から 4×2−1 = 7 トークン分 (空白込み、アーキテクチャ編参照)の隠れ状態を切り出し、 出力プロジェクタで (1, 77, 1024) の prompt_embeds に変換して、 Stable Diffusion にテキストの代わりに渡します。

nextgpt/model/language_model/nextgpt_llama.py L745–773(抜粋) GitHub ↗
for gen_idx in all_gen_idx:
    end_idx = gen_idx + n_img_tokens*2-1
    gen_list = generated_ids[0, gen_idx:end_idx:2].cpu().detach().numpy().tolist()  # ストライド2で空白を飛ばす
    assert gen_list == _image_sigal_token_indices    # <image_00>…<image_03> が揃っているか検証
    raw_emb = embeddings[:, gen_idx:end_idx, :]      # (1, 7, 4096) 隠れ状態

    # Produce generation embedding.
    gen_prefix = generated_ids[0, gen_idx:end_idx]
    gen_prefix_embs = self.get_input_embeddings()(gen_prefix)          # シグナルトークンの入力埋め込み
    gen_emb = self.get_output_image_projector()(raw_emb, gen_prefix_embs)  # (1, 77, 768/1024)

    image_outputs = generation_model(prompt_embeds=gen_emb,            # ← テキストの代わりに渡す
                                     guidance_scale=guidance_scale,    # classifier-free guidance
                                     num_inference_steps=num_inference_steps).images

モダリティごとの呼び出しパラメータは以下の通りです(predict.py の既定値)。

モダリティパイプライン条件の渡し方主なパラメータ
画像StableDiffusionPipeline(SD2)prompt_embeds (1, 77, 1024)guidance 7.5 / 50 steps
動画TextToVideoSDPipeline(ZeroScope)prompt_embeds (1, 77, 1024)320×576 / 16 フレーム / 50 steps
音声AudioLDMPipelineprompt_embeds (1, 512) → クラス埋め込み5.0 秒 / guidance 7.5 / 50 steps
classifier-free guidance との関係 拡散パイプライン内部では通常どおり $$\tilde\epsilon_\theta = \epsilon_\theta(z_t, t, \varnothing) + s \cdot \big(\epsilon_\theta(z_t, t, c) - \epsilon_\theta(z_t, t, \varnothing)\big), \quad s = 7.5$$ が実行されます。条件 \(c\) が「CLIP でエンコードしたテキスト」から 「LLM の隠れ状態をプロジェクタで変換したもの」に置き換わっただけで、 拡散モデル側には一切の改変・再学習が不要 — これが Stage 2 で 埋め込み空間を CLIP 出力に揃えておいたことの利得です。

まとめ: 役割分担の妙

  • 「何を・いつ・どのモダリティで」は離散トークンが決める — シグナルトークンの出現自体は語彙上の確率的な選択で、\(\mathcal{L}_{\text{text}}\) で学習済み
  • 「どんな内容か」は連続ベクトルが運ぶ — シグナルトークン位置の隠れ状態には直前の文脈(何の画像を頼まれたか)が凝縮されており、 プロジェクタがそれを拡散モデルの言葉に翻訳する
  • 生成品質は凍結された拡散モデルがそのまま担保する

離散(トークン)と連続(埋め込み)のハイブリッドでモダリティ間を橋渡しする — これが NExT-GPT の "any-to-any" の実体です。
