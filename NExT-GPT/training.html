2. 学習プロセス

凍結された巨大モデル群の「すき間」だけを、3 ステージに分けて学習する。 各ステージの役割と、テキスト損失・整合損失・拡散損失の数式⇔コード対応を追います。

3 ステージの全体像

NExT-GPT の学習は、共通のエントリポイント train.py を フラグを変えて 3 回実行することで進みます (scripts/pretrain_enc.sh → pretrain_dec.sh → finetune.sh)。 どのステージでも ImageBind・Vicuna・拡散モデル本体は凍結のままで、 学習されるのは接続部だけです。下図は各ステージで 🔥 が付く場所の移り変わりです。

凍結の制御は train.py で「全部凍結してから、フラグの立った部分だけ解凍する」素直な実装です。

損失関数の全体像 — forward を読む

すべての損失は NextGPTLlamaForCausalLM.forward の中で計算され、 単純に足し算されます。

全体の損失 $$\mathcal{L} \;=\; \mathcal{L}_{\text{text}} \;+\; \sum_{x \,\in\, \{\text{img},\, \text{vid},\, \text{aud}\}} \Big( \mathcal{L}^{x}_{\text{cap}} + \mathcal{L}^{x}_{\text{gen}} \Big)$$ どの項が有効になるかはバッチのデータ種別で決まります(キャプション埋め込みやターゲット画像が バッチに含まれていれば対応する項が計算される、という実装)。
nextgpt/model/language_model/nextgpt_llama.py L226–257(抜粋) GitHub ↗
text_loss = outputs.loss          # ① LlamaForCausalLM 標準の next-token CE
loss = text_loss

has_img_gen_loss = True if target_images is not None or target_images_feature is not None else False
_loss, img_cap_loss, img_loss = self.compute_image_loss(
    image_caption_embeddings, image_captions,
    target_images=target_images, has_gen_loss=has_img_gen_loss, has_snr_loss=True,
    labels=labels, image_signal_token_indices=image_signal_token_indices,
    hidden_states=outputs.hidden_states)
if _loss is not None:
    loss = loss + _loss           # ② 画像の cap_loss + gen_loss を加算

# ③④ compute_video_loss / compute_audio_loss も同様(has_snr_loss=False)

① テキスト損失 \(\mathcal{L}_{\text{text}}\)

通常の言語モデル損失(次トークン予測の交差エントロピー)です。 シグナルトークンも語彙の一部なので、「どこで <image_00> を書き始めるか」も この損失で学習されます。

数式 $$\mathcal{L}_{\text{text}} = -\frac{1}{T}\sum_{t=1}^{T} \log p_\theta\!\left(y_t \mid y_{<t},\, X\right)$$ \(y\) は応答トークン列(シグナルトークンを含む)、\(X\) はマルチモーダル入力。 挿入された画像特徴などの位置は IGNORE_INDEX のため対象外です。

② キャプション整合損失 \(\mathcal{L}_{\text{cap}}\) — 「教師はテキストエンコーダ」

シグナルトークン位置の隠れ状態を出力プロジェクタで変換した結果 \(P_{\text{out}}(\mathbf{h}_S)\) を、 凍結された拡散モデルのテキストエンコーダにキャプションを通した埋め込み \(E_{\text{text}}(c)\) に近づけます。

数式とコードの対応 $$\mathcal{L}_{\text{cap}} = \frac{1}{N L}\sum_{i=1}^{N}\sum_{\ell=1}^{L} \big\lVert\, P_{\text{out}}(\mathbf{h}_S)_{i\ell} - E_{\text{text}}(c)_{i\ell} \,\big\rVert_2$$ コードの l2_loss は位置ごとのユークリッド距離 (((u - v) ** 2).sum(dim=-1) ** 0.5)を返し、.mean() で平均しています。

教師埋め込みは事前計算しておく \(E_{\text{text}}(c)\) は学習中に毎回計算せず、preprocess_embeddings.py で 各キャプションを凍結パイプラインに通した結果 (pipe(batch_captions, return_prompts_only=True))を .npy として ./data/embed/ に保存し、データローダが読み込みます (pretrain_dec.sh の --*_caption_emb_folder)。

③ 拡散生成損失 \(\mathcal{L}_{\text{gen}}\) — 「プロジェクタ出力で本当に生成できるか」

整合損失だけでは埋め込み空間が揃うだけで、生成品質は保証されません。 そこで実際にターゲット画像を VAE で潜在変数にし、ノイズを載せ、 プロジェクタ出力を条件として UNet にノイズ予測させる 標準的な拡散損失も併用します。UNet は凍結なので、勾配は条件(=プロジェクタ)側に流れます。

数式とコードの対応 $$\mathcal{L}_{\text{gen}} = \mathbb{E}_{z_0,\, \epsilon \sim \mathcal{N}(0,I),\, t} \Big[\, w(t)\,\big\lVert \epsilon - \epsilon_\theta\big(z_t,\, t,\, P_{\text{out}}(\mathbf{h}_S)\big) \big\rVert^2 \,\Big], \qquad z_t = \sqrt{\bar\alpha_t}\, z_0 + \sqrt{1-\bar\alpha_t}\,\epsilon$$ 画像のみ Min-SNR 重み \(w(t) = \min(\mathrm{SNR}(t),\, 5)\,/\,\mathrm{SNR}(t)\) を使用 (has_snr_loss=True、compute_snr は Min-SNR Diffusion Training の実装を移植)。 動画・音声は \(w(t)=1\) の素の MSE です。
nextgpt/model/language_model/nextgpt_llama.py L351–387(抜粋) GitHub ↗
latents = self.get_image_vae().encode(target_images).latent_dist.sample()
latents = latents * self.get_image_vae().config.scaling_factor

noise = torch.randn_like(latents)                                  # ε
timesteps = torch.randint(0, num_train_timesteps, (bsz,), ...)     # t をランダムに選ぶ
noisy_latents = self.get_image_noise_scheduler().add_noise(latents, noise, timesteps)  # z_t

target = noise
model_pred = self.get_image_unet()(noisy_latents, timesteps, projected_embeddings).sample  # ε_θ(z_t, t, c)

if has_snr_loss:   # Min-SNR 重み付け(画像のみ)
    snr = self.compute_snr(timesteps, self.get_image_noise_scheduler())
    mse_loss_weights = (torch.stack([snr, 5 * torch.ones_like(timesteps)], dim=1).min(dim=1)[0] / snr)
    gen_loss = F.mse_loss(model_pred.float(), target.float(), reduction="none")
    gen_loss = gen_loss.mean(dim=list(range(1, len(loss.shape)))) * mse_loss_weights
    gen_loss = gen_loss.mean()
else:
    gen_loss = F.mse_loss(model_pred.float(), target.float(), reduction="mean")
loss += gen_loss

Stage 1: エンコード側アラインメント(pretrain_enc.sh)

「画像/動画/音声 → その説明文」というキャプション対 (cc3m_enc / webvid_enc / audiocap_enc)を使い、 X を見てキャプションをテキスト生成するタスクで 入力プロジェクタを学習します。応答は普通のテキストなので、効いてくる損失は \(\mathcal{L}_{\text{text}}\) です。ImageBind の埋め込みが LLM にとって 「読める外国語」から「母語」になるステージと言えます。

scripts/pretrain_enc.sh(要点) GitHub ↗
--dataset_name_list audiocap_enc webvid_enc cc3m_enc \
--tune_mm_input_adapter True \            # 🔥 入力プロジェクタのみ解凍
--mm_input_projector_type group \
--freeze_mm_output_img_adapter True \     # 出力側 3 つは凍結のまま
--freeze_mm_output_vid_adapter True \
--freeze_mm_output_aud_adapter True \
--n_img_tokens 4  --n_vid_tokens 24  --n_aud_tokens 8 \
--learning_rate 1e-3                      # プロジェクタだけなので大きめの学習率

Stage 2: デコード側アラインメント(pretrain_dec.sh)

今度は逆向きの「説明文 → X」データ(cc3m_dec など)を使います。 応答側にシグナルトークン列が埋め込まれた教師データで、

  1. \(\mathcal{L}_{\text{text}}\): 適切な場所でシグナルトークンを書き出すことを学習
  2. \(\mathcal{L}_{\text{cap}}\): シグナルトークンの隠れ状態が「キャプションの意味」を運ぶよう出力プロジェクタを学習
  3. \(\mathcal{L}_{\text{gen}}\): その埋め込みで実際にターゲット X が復元できるよう微調整

の 3 つが同時に働きます。Stage 1 で学習した入力プロジェクタは --pretrain_mm_input_adapter で読み込んだうえで凍結します。

scripts/pretrain_dec.sh(要点) GitHub ↗
--dataset_name_list audiocap_dec webvid_dec cc3m_dec \
--pretrain_mm_input_adapter ./checkpoints/pretrain_enc_1/mm_input_projector.bin \
--freeze_mm_input_adapter True \          # Stage 1 の成果は凍結して引き継ぐ
--tune_mm_output_aud_adapter True \       # 🔥 出力プロジェクタを解凍
--freeze_mm_output_aud_adapter False \
--image_caption_emb_folder ./data/embed \ # 事前計算したキャプション埋め込み
--video_caption_emb_folder ./data/embed \
--audio_caption_emb_folder ./data/embed \
--learning_rate 2e-4
コミットされているスクリプトは「音声の回」の設定 リポジトリの pretrain_dec.sh は tune_mm_output_aud_adapter True のみ 🔥 で、 画像・動画の出力プロジェクタは凍結になっています。3 つの出力プロジェクタは独立なので、 モダリティごとにフラグを差し替えて実行する(または 3 つ同時に True にする)使い方が想定されています。

Stage 3: 指示チューニング(finetune.sh)

最後に、モダリティを跨ぐ対話・指示追従を教えます。データは LLaVA / Alpaca / VideoChat などの既存指示データに加え、 本論文が構築した MosIT(Modality-switching Instruction Tuning、 モダリティの切り替えを含む多ターン対話 5K)を使用。 このステージで初めて LLM 本体に LoRA が入ります。

プロジェクタ類を LLM 本体(LoRA)と別の学習率で動かすため、 nextgpt_trainer.py の create_optimizer が mm_input_projector_lr / mm_output_projector_lr 指定時に パラメータグループを分けています (nextgpt_trainer.py L180–)。

設計の核心 「LLM とエンコーダを繋ぐ」「LLM と生成モデルを繋ぐ」という 2 つの翻訳問題を 先に別々に解いておき(Stage 1–2)、最後に全体の振る舞いだけを LoRA で整える(Stage 3)。 巨大モデルはすべて凍結のまま、更新されるのは全体の約 1% — これが NExT-GPT が 1 桁 GPU で学習できる理由です。
