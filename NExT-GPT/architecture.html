1. アーキテクチャ詳解

ImageBind エンコーダから拡散デコーダまで、NExT-GPT を構成する 5 つの部品を テンソル形状を追いながらコードで確かめます。

5 つの構成部品

NExT-GPT のモデル定義は nextgpt/model/nextgpt_arch.py の NextGPTMetaModel に集約されています。コンストラクタを見ると、 モデルが 5 種類の部品の組み立てであることがそのまま読み取れます。

③(LLM 本体)は nextgpt/model/language_model/nextgpt_llama.py の NextGPTLlamaForCausalLM で、HuggingFace の LlamaForCausalLM を継承しつつ 上の NextGPTMetaModel を混ぜ込む、LLaVA と同じ多重継承スタイルです。

① ImageBind エンコーダ — 3 モダリティを 1 本で

入力側のエンコーダは 1 つだけです。ImageBind は画像・動画・音声(ほか計 6 モダリティ)を 同一の埋め込み空間に写像するモデルなので、モダリティごとに別々のエンコーダと プロジェクタを用意する必要がありません。ラッパの forward は モダリティ名で入力を振り分けるだけの薄い実装です。

nextgpt/model/multimodal_encoder/imagebind_encoder.py L57–81(抜粋) GitHub ↗
@torch.no_grad()                      # ← エンコーダは常に勾配なし=凍結
def forward(self, inputs, modality='image'):
    _inputs = {}
    if modality == 'image':
        _inputs.update({ModalityType.VISION: inputs})  # [1, 3, 224, 224]
        _modality = ModalityType.VISION
    elif modality == 'audio':
        _inputs.update({ModalityType.AUDIO: inputs})   # [1, 3, 1, 128, 204]
        _modality = ModalityType.AUDIO
    elif modality == 'video':
        _inputs.update({ModalityType.VISION: inputs})  # [1, 15, 3, 2, 224, 224]
        _modality = ModalityType.VISION
    ...
    embeddings = self.multimodal_tower(_inputs)
    return embeddings[_modality]
ポイント: 出力は「1 入力 = 1 ベクトル」 ImageBind の出力はパッチ列ではなく、入力 1 件につき 1 本のグローバル埋め込み(1024 次元)です。 動画も ImageBind 内部でフレームを集約して 1 本になります。したがって LLM の系列に挿入される マルチモーダル「トークン」は非常にコンパクトで、これが NExT-GPT の軽量さの源泉です (パッチ 576 トークンを挿入する LLaVA-1.5 との大きな違い)。 音声は [3, 1, 128, 204] = メルスペクトログラムの 3 クリップとして入ります。

② 入力プロジェクタ — LLM が読める表現へ

ImageBind の 1024 次元埋め込みを Vicuna の隠れ次元 4096 に写像します。 プロジェクタ種別は設定で切り替えられ(linear / mlp / group)、 学習スクリプトでは --mm_input_projector_type group が指定されています。

nextgpt/model/multimodal_projector/builder.py L49–64(抜粋) GitHub ↗
def build_input_projector(config, delay_load=False, **kwargs):
    projector_type = getattr(config, "mm_input_projector_type", "linear")
    if projector_type == "linear":
        return nn.Linear(in_features=config.mm_hidden_size, out_features=config.hidden_size)
    if projector_type == "mlp":
        return MLP(in_features=config.mm_hidden_size, out_features=config.hidden_size, num_layers=2)
    if projector_type == "group":
        return GroupProjector(in_features=config.mm_hidden_size,   # 1024 (ImageBind)
                              out_features=config.hidden_size,     # 4096 (Vicuna-7B)
                              **kwargs)

GroupProjector(projector.py)は GroupViT 由来の グルーピング機構で、入力トークン列を学習可能なグループトークンに段階的に集約します (64 グループ → 8 グループ)。論文でいう “concept-level” のアラインメント — パッチの寄せ集めではなく意味概念の単位で LLM に渡す — をここが担います。

エンコードの呼び出し側はシンプルで、タワー → プロジェクタの 2 段です。

③′ シグナルトークン — LLM に「生成の指示書」を書かせる語彙

出力側の鍵がシグナルトークンです。モデル初期化時にトークナイザへ 画像 4 個・動画 24 個・音声 8 個の特殊トークンを追加し、 埋め込み行列も拡張します(新規行は既存埋め込みの平均で初期化)。

nextgpt/model/nextgpt_arch.py L585–605(抜粋) GitHub ↗
def initialize_vision_tokenizer(self, model_args, tokenizer):
    # add modality tokens
    signal_token_list = []
    signal_token_list.extend([f"<image_{i:02d}>" for i in range(model_args.n_img_tokens)])  # 4 個
    signal_token_list.extend([f"<video_{i:02d}>" for i in range(model_args.n_vid_tokens)])  # 24 個
    signal_token_list.extend([f"<audio_{i:02d}>" for i in range(model_args.n_aud_tokens)])  # 8 個

    num_new_tokens = tokenizer.add_tokens(signal_token_list, special_tokens=True)
    self.resize_token_embeddings(len(tokenizer))
    if num_new_tokens > 0:
        input_embeddings  = self.get_input_embeddings().weight.data
        output_embeddings = self.get_output_embeddings().weight.data
        input_embeddings_avg  = input_embeddings[:-num_new_tokens].mean(dim=0, keepdim=True)
        output_embeddings_avg = output_embeddings[:-num_new_tokens].mean(dim=0, keepdim=True)
        input_embeddings[-num_new_tokens:]  = input_embeddings_avg   # 平均ベクトルで初期化
        output_embeddings[-num_new_tokens:] = output_embeddings_avg

学習データ側では、応答テキスト中の <image> をシグナルトークン列に展開します。 このときスペース区切りで連結される点が重要です。

nextgpt/dataset/dataset_utils.py L184–186(抜粋) GitHub ↗
# if the GPT output image or video or audio, it should be replaced by the signal tokens.
sentence["value"] = sentence["value"].replace(
    DEFAULT_IMAGE_TOKEN,
    ' '.join([f"<image_{i:02d}>" for i in range(data_args.n_img_tokens)]))
なぜコードのあちこちに「n×2 − 1」が現れるのか スペース区切りのため、トークナイズ後の系列は <image_00> ▁ <image_01> ▁ <image_02> ▁ <image_03> のように シグナルトークンと空白トークンが交互に並び、長さは 4×2−1 = 7 になります。 損失計算(nextgpt_llama.py L327)や生成時の検出(同 L747 の generated_ids[0, gen_idx:end_idx:2]、 ストライド 2 で 1 個おきに取り出す)に出てくる len(signal_token_indices)*2-1 はこの空白込みの長さです。

④ 出力プロジェクタ — 隠れ状態を「拡散モデルの言葉」に翻訳

LLM がシグナルトークンを出したら、その位置の隠れ状態を拡散モデルが理解できる 条件埋め込みに変換する必要があります。これを担うのが各モダリティの出力プロジェクタ (--mm_output_*_projector_type transformer)で、実体は 4 層エンコーダ + 4 層デコーダの小さな Transformer です。

nextgpt/model/multimodal_projector/projector.py L224–249(抜粋) GitHub ↗
class TransformersProjector(nn.Module):
    def __init__(self, in_features, out_features, num_query_token, **kwargs):
        super().__init__()
        hidden_dim = 512
        self.in_fc = nn.Linear(in_features, hidden_dim)          # 4096 → 512
        self.tfm = nn.Transformer(batch_first=True, norm_first=True,
                                  d_model=hidden_dim, num_encoder_layers=4, num_decoder_layers=4,
                                  dim_feedforward=hidden_dim * 4, dropout=0.0, nhead=4)
        self.out_fc = nn.Linear(hidden_dim, out_features)        # 512 → 1024(SD2)等
        self.query_embs = nn.Parameter(torch.randn(1, num_query_token, hidden_dim))  # 77 個の学習可能クエリ

    def forward(self, x, input_embs):
        x = x + input_embs                # 隠れ状態 + シグナルトークンの入力埋め込み
        x = self.in_fc(x)
        x = self.tfm(x, self.query_embs.repeat(x.shape[0], 1, 1))  # クエリが情報を吸い上げる
        outputs = self.out_fc(x)
        return outputs                    # (b, 77, 1024) など
