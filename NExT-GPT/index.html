NExT-GPT 図解

テキスト・画像・動画・音声を自由に入出力する Any-to-Any マルチモーダル LLM「NExT-GPT」(ICML 2024 Oral)の 学習と生成のプロセスを、実装コードの引用とアニメーション図解で読み解きます。

NExT-GPT とは

NExT-GPT (Wu+, ICML 2024)は、 シンガポール国立大学 NExT++ 研究センターが発表した エンドツーエンドの Any-to-Any マルチモーダル LLM です。 テキスト・画像・動画・音声の任意の組み合わせを入力として理解し、 任意の組み合わせで出力(生成)できます。

最大の特徴は、既存の強力な事前学習済みモデルを「接着」する設計にあります。

  • 入力側: マルチモーダルエンコーダ ImageBind が画像・動画・音声を共通の埋め込み空間へ変換
  • 中核: LLM として Vicuna-7B(LLaMA-2 ベース)が理解・推論を担当
  • 出力側: Stable Diffusion 2(画像)、ZeroScope v2 XL(動画)、AudioLDM(音声)という既製の拡散モデルが生成を担当

これらの間を小さな射影層(プロジェクタ)だけで結び、 巨大なエンコーダ・LLM・拡散モデル本体は凍結したまま、 全パラメータのわずか約 1% のみを学習します。 LLM が「何をどのモダリティで出力すべきか」を伝える手段が、 語彙に追加されたシグナルトークン(<image_00> など)です。

このシリーズで読むコード 解説は公式リポジトリ NExT-GPT/NExT-GPT の現行コードベース(LLaVA スタイルに再編された nextgpt/ ディレクトリ、コミット 60d618b 時点)に基づきます。 旧実装は NExT-GPT-Lagacy/ に退避されており、README も新コードベースの利用を推奨しています。

全体アーキテクチャ

まず全体像です。データは下図のように 「エンコード → 入力射影 → LLM 推論 → シグナルトークン → 出力射影 → 拡散デコード」 の順に流れます(図は自動でループ再生されます)。

論文との対応 この図は論文 Figure 1 の「Multimodal Encoding Stage → LLM Understanding and Reasoning Stage → Multimodal Generation Stage」の 3 段構成に対応します。 論文で “concept-level alignment” と呼ばれる工夫(パッチ単位ではなく概念単位のトークンに集約する GroupProjector)は アーキテクチャ編で詳しく見ます。

学習と生成の見どころ(ダイジェスト)

学習は 3 ステージ

ステージスクリプト学習するもの 🔥目的
1. エンコード側
アラインメント		 scripts/pretrain_enc.sh 入力プロジェクタ ImageBind の特徴を LLM が「読める」表現に揃える(X→テキスト生成で学習)
2. デコード側
アラインメント		 scripts/pretrain_dec.sh 出力プロジェクタ シグナルトークンの隠れ状態を、拡散モデルのテキスト条件空間に揃える
3. 指示チューニング scripts/finetune.sh LoRA + 両プロジェクタ MosIT データ等でモダリティ切替を含む指示追従能力を獲得

損失は テキスト生成損失 + キャプション整合損失(cap_loss)+ 拡散生成損失(gen_loss) の和で、 すべて nextgpt/model/language_model/nextgpt_llama.py の forward に実装されています。 数式とコードの対応は学習編で追いかけます。

生成はシグナルトークンが鍵

推論時、LLM の出力に <image_00> <image_01> … のようなシグナルトークン列が現れると、 その位置の最終層の隠れ状態が抜き出され、出力プロジェクタで 77×768 の prompt_embeds(CLIP テキスト埋め込み互換)に変換されて拡散パイプラインに渡されます。 つまり「テキストプロンプトの代わりに LLM の思考ベクトルで画像を生成する」のが NExT-GPT の生成プロセスです。詳細は生成編へ。
