2. 学習の仕組み

「次の単語」と「次に生成するモダリティの意味」を、同じ instruction sequence から学びます。

教師データ：interleaved instruction

訓練例は単発の caption pair だけでなく、テキストとモダリティが交互に現れる instruction / response として整形されます。teacher forcing により応答 token の正解を与え、入力側のモダリティは encoder feature に置換します。

CoDi-2/train.py — training entry point公式コードで確認 ↗
# Training follows the standard forward / backward contract:
outputs = model(**batch)
loss = outputs.loss
loss.backward()
optimizer.step()

上は学習ループの責務を抜き出した短い読み替えです。核心は model(**batch) 内で、言語 token の損失とモダリティ feature の損失を対応する位置にだけ課す点です。

二種類の教師信号

目的関数の読み方概念的には \(\mathcal L = \mathcal L_{LM} + \lambda\mathcal L_{feature}\)。前者は正解 token に対する cross entropy、後者は output projector が予測した連続特徴と、対象画像・音声を encoder した特徴との距離（整列）です。係数 \(\lambda\) が二つのスケールを調整します。

なぜ diffusion 自体を毎回 end-to-end 学習しないのか

LLM が画素列や波形列を直接予測すると系列が極端に長くなります。CoDi-2 は意味を表す比較的短い条件 feature を予測し、既に高品質な生成能力を持つ diffusion decoder に具体化を委ねます。これにより instruction following の学習と sample 品質の学習を分離できます。

学習時に確認するマスク

  1. ユーザー prompt の token は文脈として見せるが、通常は LM loss の対象外。
  2. assistant の言語区間は次 token loss の対象。
  3. モダリティ出力位置の hidden states だけを集約し、target feature と比較。
  4. padding は attention と loss の両方から除外。
重要feature loss は完成画像との pixel loss ではありません。LLM と生成器の間で受け渡す「意味条件」を合わせる損失です。
