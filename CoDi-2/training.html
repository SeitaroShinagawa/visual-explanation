2. 学習プロセス

「トークンを当てる」学習と「ベクトルの向きを合わせる」学習が、 1 つの forward の中で同時に走ります。 マスクの作り方から 3 種類の損失まで、数式⇔コードで追いかけます。

この章を読む前に 公開リポジトリには学習ループ(train スクリプト)もデータセットも含まれていません。 本章が読むのは OpenLLAMAPEFTModel.forward —— 「1 バッチを受け取って損失を返す関数」です。 その入口の形と損失の定義から、CoDi-2 が何を学ぼうとしているかは十分に読み取れます。
論文の損失とコードの損失は 1 対 1 で対応する 論文 §3.2 が定める最終的な学習損失は次の 3 項です。 $$\mathcal{L} \;=\; \alpha\,\mathrm{MSE}\big(c_{\text{MLLM}},\, C_x(x)\big) \;+\; \mathcal{L}_{DM} \;+\; \mathcal{L}_t$$ これは forward が計算する 3 つの損失とそのまま対応します。
論文コード本章の節
\(\mathcal{L}_t\)(text token prediction loss)loss = outputs.loss①
\(\alpha\,\mathrm{MSE}(c_{\text{MLLM}}, C_x(x))\)feature_loss(係数 0.1 = \(\alpha\))②
\(\mathcal{L}_{DM}\)(diffusion generation loss)diffusion_loss③
以下ではこの対応を 1 項ずつ確かめていきます。

学習データの形 — 会話を 1 本の系列に潰す

学習サンプルは {'from': 'human'|'gpt', 'value': ...} のターン列です。 build_one_instance がこれをトークン列に変換し、 人間のターンは -100 で塗りつぶして損失対象から外すという、 指示チューニングの定番の処理を行います。

CoDi-2/core/models/mmllama/openllama.py L58–86 GitHub ↗
def build_one_instance(tokenizer, conversation):
    text_list = []
    turn_num = len(conversation)
    input_ids, target_ids = [], []
    for i in range(turn_num):
        turn = conversation[i]
        role = turn['from']
        if i == 0: # the first human turn
            assert role == 'human'
            text = '</Perception> ' + turn['value']        # ★ 冒頭に知覚パートの終端マーカー
            one_input_id = tokenizer(text, add_special_tokens=False).input_ids
            input_ids += one_input_id
            target_ids += [-100]*len(one_input_id) # do not perform loss regression on human prompt
        else:
            if role == 'human':
                text = turn['value']
                one_input_id = tokenizer(text, add_special_tokens=False).input_ids
                input_ids += one_input_id
                target_ids += [-100]*len(one_input_id)      # 人間の発話は学習しない
            elif role == 'gpt':
                text = turn['value']
                one_input_id = tokenizer(text, add_special_tokens=False).input_ids
                input_ids += one_input_id
                target_ids += one_input_id                  # モデルの発話だけを学習する
            else:
                raise Exception('Wrong Role!!!')
        text_list.append(text)
        assert len(input_ids) == len(target_ids)
    return text_list, input_ids, target_ids

ファイル冒頭には PROMPT_START = '<Perception>'(L103)も定義されており、 「<Perception> …画像/音声の特徴… </Perception> 指示文」という プロンプト構造が想定されていることが読み取れます。

ラベルの二重構造 — 同じ位置を CE から外し、回帰へ回す

CoDi-2 の学習で最も味わい深いのが prompt_wrap の後半です。 ここでは1 つの位置に対して 2 種類のラベルが作られ、片方だけが有効になります。

  1. モデルの応答に含まれる FEATURE_ID の位置を探す(target_replace)
  2. その位置に、ImageBind が返した本物の特徴を regression_targets として書き込む
  3. 同じ位置の target_ids を -100 にして、テキスト CE の対象から外す

つまり「この位置ではトークンを当てるのではなく、ベクトルを当てろ」という指示が、 ラベルの作り分けだけで表現されています。

論文が言う \(C_x(x)\) がこれ 論文 §3.2 は、LLM に予測させる目標を “we explicitly induce that \(c = C_x(x)\)” —— つまり 「生成すべきターゲット \(x\) を、条件エンコーダ \(C_x\) に通したもの」と定めています。 コードの targets_tmp = encoder_embeds_raw[i][-1:] はまさにこれで、 ターゲットを ImageBind に通した特徴が回帰の教師になります。 拡散モデルから見れば、自分のエンコーダが作るはずだった値を LLM が代わりに書いてくれる形になり、 論文の言葉では “DM is expected to function as an autoencoder” という状況です。
教師は「そのサンプルの最後の要素」 targets_tmp = encoder_embeds_raw[i][-1:] —— 教師特徴として使われるのは、 そのサンプルに与えられた画像リストの最後の 1 枚を ImageBind に通したものです。 in-context 学習用のデータでは「例示 → 例示 → お手本の答え」という並びになるため、 最後に置かれた画像が「生成すべき正解画像」という約束になっている、と読めます。

損失の全体像

forward は (loss, gen_acc, feature_loss) を返します。 損失の合成(重み付け)は呼び出し側の学習ループ(非公開)に委ねられていますが、 feature_loss の中身にはすでに係数 0.1 が掛かっています。

全体の損失(論文 §3.2 とコードの対応) $$\mathcal{L} \;=\; \underbrace{\mathcal{L}_t}_{\texttt{outputs.loss}} \;+\; \underbrace{\alpha\,\mathrm{MSE}\big(c_{\text{MLLM}},\, C_x(x)\big)}_{\texttt{feature\_loss}\;(\alpha = 0.1)} \;+\; \underbrace{\mathcal{L}_{DM}}_{\texttt{diffusion\_loss}}$$ コードでは第 2 項と第 3 項がどちらも feature_loss という 1 つの変数に足し込まれ、 第 3 項は perception_type == 'clip-diffusser-back-proop' のときだけ加算されます。
論文は MSE、コードの主経路はコサイン 第 2 項について、論文は明確に MSE と書いていますが、 公開コードの 'clip' 経路が実際に計算するのは負のコサイン類似度です。 literal な MSE を計算しているのは 'vae' 経路のほうですが、 そちらは後述のとおり公開コードのままでは実行できません。 ImageBind 特徴を扱う 'clip' 経路では、 スケールを揃える必要がないぶんコサインのほうが素直だという判断だと考えられますが、 論文の式とコードが厳密には一致しない箇所なので、そのまま記しておきます。

① テキスト損失 \(\mathcal{L}_{\text{text}}\)

HuggingFace の LlamaForCausalLM に labels を渡すだけで得られる、標準の言語モデル損失です。

数式 $$\mathcal{L}_{\text{text}} = -\frac{1}{|\mathcal{T}|}\sum_{t \in \mathcal{T}} \log p_\theta\!\left(y_t \mid y_{<t},\, X\right)$$ \(\mathcal{T}\) は target_ids が \(-100\) でない位置の集合、 つまりモデルの応答テキストのうち特徴位置を除いた部分です。 \(X\) は入力列に差し込まれたマルチモーダル特徴。

② 特徴回帰損失 \(\alpha\,\mathrm{MSE}(c_{\text{MLLM}}, C_x(x))\) — 「向き」だけを合わせる

CoDi-2 の心臓部です。L2 距離ではなくコサイン類似度を使っている点、 そして 予測側だけを L2 正規化している点に注目してください。

数式とコードの対応 $$\mathcal{L}_{\text{feat}} \;=\; -\,\frac{1}{|\mathcal{F}|}\sum_{(i,t)\,\in\,\mathcal{F}} \cos\!\Big(\, P_{\text{out}}\big(\mathbf{h}^{(i)}_{t-1}\big),\; \mathbf{v}^{(i)}_{t} \Big)$$ \(\mathcal{F}\) は indice_mask が True の位置、 \(\mathbf{h}_{t-1}\) は1 つ手前の最終層隠れ状態、 \(\mathbf{v}_t\) は ImageBind が返した教師特徴。 コサインなのでノルムは学習されず、向きだけが揃えられます。
なぜ 1 つずらすのか — これは「次特徴予測」 hidden_states[-1][:, :-1] と regression_targets[:, 1:] という組み合わせは、 次トークン予測でおなじみの shift とまったく同じ形です。 つまり CoDi-2 は「次に来るのはこの特徴だ」を予測する自己回帰モデルとして訓練されており、 テキストと特徴で学習の枠組みが完全に揃っています。 論文 Abstract の “autoregressively generate … in the continuous feature space”、 および結論の “autoregressively produce the latent features that is fed to diffusers” は、 この 1 行に対応します。
なぜコサインで足りるのか 生成編で見るように、この特徴は最終的に unCLIP の noise_augmentor に渡されます。 CLIP/ImageBind 系の埋め込み条件はもともと方向情報が本質で、 ImageBind 側の教師も CLS のノルムで割って正規化されています。 そのためスケールを合わせる必要がなく、コサインで十分という設計になっています。 NExT-GPT が L2 距離を使うのは、あちらの教師が 「CLIP テキストエンコーダの出力そのもの」という、スケールまで含めて意味のある値だからです。

③ 拡散損失 \(\mathcal{L}_{DM}\) — 生成器に通して確かめる

埋め込みの向きが合っていても、実際に良い絵が出るとは限りません。 そこで perception_type に 'clip-diffusser-back-proop' を指定すると、 LLM が生成した特徴を条件に凍結拡散モデルを 1 ステップ回し、そのノイズ予測誤差を足す 経路が有効になります。関数名の back-proop(back-prop)が示すとおり、 狙いは拡散モデルを貫いて LLM まで勾配を流すことです。

論文 §3.2 の式(1) $$\mathcal{L}_{DM} = \mathbb{E}_{z,\epsilon,t}\big\lVert \epsilon - \epsilon_\theta\big(z_t,\, t,\, C_y(y)\big)\big\rVert_2^2$$ \(y\) は条件モダリティ、\(C_y\) はその条件エンコーダ、\(\epsilon_\theta\) は UNet、 \(z_t\) は時刻 \(t\) のノイズ潜在です。 CoDi-2 はこの \(C_y(y)\) の位置にLLM が生成した特徴 \(c_{\text{MLLM}}\) を差し込みます。 論文 §1 いわく “the gradient obtained from the diffusion models' generation loss also directly back-propagates to the LLM which can enhance the perceptual faithfulness to the inputs including images or audio”。

ここで regression_logits(正規化前)を使っている点が重要です。 コサイン損失は正規化後のベクトルに掛かりますが、拡散モデルには生のスケールのまま渡されます。 つまりこの経路は「コサインでは決まらないノルムを、生成品質から決めさせる」役割も担っています。

コードが実際に計算している形 $$\mathcal{L}_{DM} = \mathbb{E}_{z_0,\,\epsilon,\,t} \Big[\, \big\lVert\, \epsilon_{\text{tgt}} - \epsilon_\theta\big(z_t,\, t,\, [\,c_{\text{txt}},\, \mathrm{aug}(P_{\text{out}}(\mathbf{h}))\,]\big) \big\rVert^2 \,\Big]$$ UNet \(\epsilon_\theta\)・VAE・テキストエンコーダはすべて凍結なので、 勾配は条件 \(P_{\text{out}}(\mathbf{h})\) を通って codi_llama_decode と LoRA に届きます。 YAML の parameterization: "v" に従い、実際の予測対象は \(\epsilon\) ではなく v ですが、 「凍結生成器を通して条件を鍛える」という構図は同じです。

補足: perception_type == 'vae' — 書きかけで動かない経路

コードにはもう一つ、特徴を ImageBind ではなくVAE 潜在で扱う分岐が残っています。 こちらは向きではなく値そのものを合わせるので、素直な平均二乗誤差です。

CoDi-2/core/models/mmllama/openllama.py L402–410 GitHub ↗

ただし、この分岐は公開コードのままでは実行できません。 codi_llama_proj と codi_llama_decode が作られるのは __init__ の if 'clip' in self.perception_type: の中だけ(L171)なので、 perception_type がちょうど 'vae' のときこの条件は偽になり、 2 つの MLP はそもそも生成されません。 その状態で上のコードに入ると self.codi_llama_decode(...) が AttributeError を投げます (それ以前に prompt_wrap の self.codi_llama_proj(...) で落ちます)。

つまり 'vae' 経路は「未完成の残骸」 「どちらが本番設定か分からない 2 つの選択肢」ではありません。 公開されている範囲では 'clip' 系だけが動作する唯一の経路で、 'vae' 系はモジュールの初期化が伴っていない書きかけのコードです (外部のパッチでデコーダを別途用意しない限り動きません)。 論文が扱うのも ImageBind 特徴を使う 'clip' 系の設計なので、 本解説もそちらを主経路として読み解いています。 'vae' 経路は「特徴を VAE 潜在で扱う設計も検討されていた形跡」として見るのが妥当でしょう。

学習パイプライン — モダリティごとに順番を回す

公開コードの forward は、冒頭で if 'image' in inputs / elif 'text' / elif 'audio' と分岐しており、 1 バッチには 1 モダリティしか入らない作りになっています。 一見すると手抜きに見えますが、これは論文の学習方針そのものです。

論文 §B.2 “The training pipeline involves simultaneous text, image, and audio generation via diffusion. To avoid the cumbersome and inefficient aspects of this multitasking approach, especially concerning model I/O, we alternate training phases between text, audio, and image generation. We apply LoRa with a rank of 128 for fine-tuning the model.”

3 つの拡散モデル(SD 2.1 unCLIP / AudioLDM2 / zeroscope v2)を同時に GPU に載せるのは重すぎるため、 フェーズを切り替えて 1 モダリティずつ学習するという方針です。 コードの elif の連なりは、その 1 フェーズ分を切り出したものと読めます。

学習データ — 「in-context 化」して作る

論文 §4 は、この学習を成り立たせるためのデータ構築にかなりの紙幅を割いています。 既存データセットを集めるだけでなく、それらを in-context 形式に変換するのがポイントです。

「テキストだけでマルチモーダルを学ぶ」トリック(§4.1) 最後の行がとくに面白い工夫です。ImageBind はすべてのモダリティを同じ空間に揃えるので、 テキストの一部を「そのテキストのエンコーダ特徴」に置き換えても、 LLM から見れば画像特徴が挿さっているのと同じ形になります。

    model_output = self.apply_model(x_noisy, t, cond, xtype, ctype, x_0, x_0_type, ...)

    if self.parameterization == "x0":
        target = x_start
    elif self.parameterization == "eps":
        target = noise

    loss = 0.0
    for model_output_i, target_i, xtype_i in zip(model_output, target, xtype):
        if xtype_i == 'image':
            loss_simple = self.get_pixel_loss(model_output_i, target_i, mean=False).mean([1, 2, 3])
        elif xtype_i == 'video':
            loss_simple = self.get_pixel_loss(model_output_i, target_i, mean=False).mean([1, 2, 3, 4])
        elif xtype_i == 'text':
            loss_simple = self.get_text_loss(model_output_i, target_i).mean([1])
        elif xtype_i == 'audio':
            loss_simple = self.get_pixel_loss(model_output_i, target_i, mean=False).mean([1, 2, 3])
        loss += loss_simple.mean()
    return loss / len(xtype)                # 出力モダリティ数で平均

そして CoDi-2 から使うときは、CoDi.__init__ の最後で self.freeze() が呼ばれ、全パラメータが requires_grad = False になります (codi.py L62–72)。

設計の核心 CoDi-2 の学習は「言語モデルの訓練枠組みを、そのまま連続ベクトルにも適用する」という 一点に集約されます。次トークン予測と同じ shift、同じマスク機構、同じ forward。 違うのは、出力を語彙上の分布として測るか(CE)、 1024 次元空間の向きとして測るか(コサイン)だけ。 NExT-GPT が「シグナルトークンという新しい語彙」を導入して段階的に学習したのに対し、 CoDi-2 は語彙を増やさずラベルの型だけを増やした、と言えます。
